Maya and Blender use one Unreal publishing pipeline

Change the host adapter, keep the pipeline. Each application has a small scene/export adapter and its own UI. Both call the same Python classes for publishing, sending and receiving results. Unreal runs one receiver with no host-specific import branch.

Setup and recovery guide · Shared Publisher · Contract and recovery tests

Follow one click across the boundary

  1. Host UI: “Publish & Send to Unreal” calls Publisher.publish(name, send=True). Blender uses an operator; Maya uses a Qt button callback.
  2. Shared core calls the adapter: inspect_selection() returns ordinary Python data. export_fbx(path) writes the mesh. These are the only two methods the publishing core needs from a host.
  3. Shared core commits the handoff: validate the name and mesh, export a new FBX revision, hash it, then write manifest.json. A failed export never commits a manifest.
  4. Shared transport sends: write a request naming the manifest and current receiver session into the exchange folder. The FBX contains geometry; the JSON contains identity, expected dimensions and integrity information.
  5. Unreal receives: its main-thread tick reads the request, verifies the hash, imports at the stable asset path, preserves material assignments, checks dimensions and saves. Both hosts use this exact importer.
  6. Result returns: Unreal writes a response. The host's timer calls Publisher.poll(), which displays the imported asset path or the error. “Sent” is not yet “Imported.”

This is a real same-machine file bridge. It sends explicit static-mesh revisions. It does not stream edits automatically, send executable code, or synchronize animation.

World translation is excluded from both exports: Unreal Actors own placement. Both reject skin/armatures, blend shapes/shape keys and mirrored or zero-scale transforms. Maya's centimeter requirement is explicit; Blender normalizes scene units. These are intentional adapter differences, not duplicated publishing policy.

Read BlenderAdapter beside MayaAdapter. Compare the same method names first. FBX bytes, topology triangulation and smoothing can differ while the size, pivot and intended shape agree. The current screenshots show a smoothing difference; identical shading is not a parity claim.

The receiver's source_host field is provenance, not an importer selector. destination_path + asset_name identifies the Unreal asset. Every revision changes its revision ID and hash, while the destination remains stable. Both existing Actors update because they reference that asset; the bridge does not replace Actors.

While a request is pending, a second publish/send is blocked. Check Unreal and its response file before resending. If a new export fails, the last sendable selection is cleared so Send cannot silently submit an older mesh. Immutable revision files remain available for inspection.
