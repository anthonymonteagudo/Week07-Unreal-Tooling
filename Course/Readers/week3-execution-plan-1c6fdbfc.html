Week 3 execution plan

Updated 13 September 2026 from the current instructor decisions, production handoff, 150-minute slide/demo map, and verified Maya workshop. Local course materials are the content authority. Jiaqi Zou's public wiki may inform visual design or site engineering, but none of its course content, dates, assignments, software requirements, or wording should be imported as truth.

Outcome for the week

Students should leave able to read a small Python operation, explain how Maya data enters it, run a scoped texel-density check and correction, and connect that operation to an artist-facing PySide interface. They should distinguish successful execution from verified output and identify what still requires artistic judgment.

Systems thinking is embedded rather than added as a separate lecture. Students name the system boundary (filesystem → Python → Maya → PySide → artist), inspect relevant state/context, and close the feedback loop by measuring after change and testing Apply-twice stability.

There is no Week 3 assignment. Optional practice and possible midterm tool ideas close the session without a submission, deadline, or new platform.

Phase 1 — lock the teaching contract

Do this before polishing slides.

  1. Confirm the Maya version students will actually use. Headless operation now passes in Maya 2022/Python 3.7/PySide2 and Maya 2027/Python 3.13/PySide6. The full UI must still be exercised visibly in the classroom version.
  2. State the classroom density convention explicitly:
    • map size in pixels;
    • density in pixels per current Maya linear unit;
    • active UV set;
    • world-space mesh area;
    • uniform scaling of existing UV shells around their centers.
  3. State the limits: no remap, pack, cut, sew, UDIM policy, or automatic material tiling change.
  4. Decide the asset boundary:
    • use the generated fixture as the reliable required demo;
    • substitute the actual museum mesh only if its Maya source, UV state, and reset route can be verified quickly;
    • do not make Unreal reimport a Week 3 dependency unless the source mapping is proven and rehearsal time remains.

Gate A: the class can proceed with the fixture even if the museum-source mapping remains unresolved.

Phase 2 — full Maya GUI rehearsal and hardening

The headless math and integration path passes. The full Maya GUI remains the highest priority verification gap.

Run this exact sequence in the classroom Maya version:

  1. Open fixtures/texel_density_workshop.ma.
  2. Inspect the reference, two targets, protected control, active UV set, scene units, and transforms.
  3. Run checkpoint 03 and record the read-only measurements.
  4. Predict the correction direction for each target.
  5. Run checkpoint 04; inspect UV Editor and checker appearance.
  6. Run Apply a second time and confirm the result remains within tolerance.
  7. Undo and confirm the scene returns to the previous UV state.
  8. Confirm the unselected control remains unchanged.
  9. Open, close, and reopen both PySide windows; confirm no duplicate windows or stale state.
  10. Run the completed UI path: capture reference → select targets → Check → Apply.

Harden the code only where rehearsal demonstrates a need. Priorities:

  • parent the windows reliably to Maya's main window;
  • make a multi-target Apply one understandable undo step;
  • preserve/reselect targets after UI actions when helpful;
  • test no selection, no targets, reference accidentally selected, already-matching density, multiple UV shells, missing UVs, degenerate UVs, and non-uniform transforms;
  • ensure skipped targets never appear as successful;
  • show exact units, affected scope, before/after values, and a recovery message.

Gate B: Check is visibly read-only, Apply is undoable, verification is visible, Apply-twice is stable, and protected scope is demonstrated in the full GUI.

Phase 3 — make the student package disposable and recoverable

Create a clean student release separate from instructor answers.

Required contents:

  • relative setup checkpoint that discovers the repository from the opened fixture and reports the actual Maya/Python/PySide environment;
  • generated fixture and reset/build helper;
  • checkpoints 01–05;
  • shared support package;
  • default JSON preset and designated student-output folder;
  • student modification starter and bounded TODO choices;
  • concise launch table for ordinary Python versus Maya Script Editor;
  • offline Futurecoder fallback;
  • test-case card: no selection, two targets, Apply twice, protected control;
  • troubleshooting for project root, imports, wrong interpreter, and Maya version.

Exclude instructor-completed answers, assessment data, absolute instructor paths, caches, credentials, unrelated lesson projects, and claims not verified in the target Maya version.

Verify from both a fresh clone and a ZIP extracted to a path containing spaces. The student should not need the instructor's Perforce workspace.

Gate C: a fresh student copy opens the fixture and reaches checkpoint 03 without editing paths inside source files.

Phase 5 — rehearse the learning sequence

Futurecoder

  • Rehearse the exact hosted navigation from a fresh browser state.
  • Choose one small sequence supporting conditions, loops, functions, and prediction.
  • Guided route: predict → run → interpret feedback.
  • Supported route: finish the bounded task with hints.
  • Extension route: construct a counterexample to a wrong condition.
  • Keep checkpoint 01 ready if the site or network is unavailable.

Maya and PySide

  • Rehearse with the same Maya version and screen layout used in class.
  • Reset the fixture between major demonstrations.
  • Keep commands in small pasted/runnable checkpoints rather than live-typing complex mesh API code.
  • Practice the transitions from selection → measurement → correction → verification and from widget → signal → callback → shared function → artist feedback.
  • Time the pair-role switch explicitly.

Recovery kit

Prepare:

  • clean fixture copy;
  • known-good completed code;
  • offline checkpoint 01;
  • screenshots of expected Script Editor output and both UIs;
  • one-page launch/troubleshooting guide;
  • a short route that can omit optional discussion depth without cutting the pair lab.

Gate E: a timed rehearsal fits 150 minutes and preserves the break, Maya practice, pair modification, role switch, and final questions.

Instructor decision points during class

  • If Futurecoder access costs more than two or three minutes, switch to checkpoint 01.
  • If students understand Python syntax but not Maya selection/API context, cut syntax explanation before cutting Maya practice.
  • If the live correction fails, stop at Check, use the recorded expected output, and reason about the failure. Do not improvise destructive UV operations.
  • If time runs short, reduce PySide exposition to the actual signal/callback path and keep the pair test.
  • If beginners need support, give them label/no-selection improvements; give confident students per-object reporting or a supported skip case.

Definition of ready

  • the classroom Maya version is named and tested;
  • setup succeeds from an extracted path containing spaces without editing source;
  • the fixture and reset route work from a clean student copy;
  • Check, Apply, undo, Apply-twice, and protected scope pass in the full GUI;
  • the poor and completed UIs reopen predictably;
  • Futurecoder and offline fallback are rehearsed;
  • the 21-screen deck uses real evidence and totals 150 minutes;
  • student and instructor packages are separate;
  • the local Week 3 wiki preview no longer teaches the superseded roughness-validator direction;
  • no Week 3 assignment, deadline, grade, or mandatory submission appears anywhere in the live/public materials.
