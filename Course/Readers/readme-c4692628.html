Tech Art Museum — Exhibit Review Grid

Open /Game/TechArtMuseum/SandboxGrid/L_ExhibitReviewGrid in TechArtMuseumIntegration.uproject (Unreal Engine 5.7). The saved instructor sandbox contains 12 bays, with Correct on the left and Incorrect on the right. All newly authored assessment assets are under /Game/TechArtMuseum/SandboxGrid/.

The build has completed. Fresh-process asset validation, rendered review and the limited Play probe are pending; see the evidence section before treating an observed symptom or input path as tested. This is the instructor review map, not a student release or a replacement for an existing gallery/lab map.

Open and review

  1. Save any work already open in your editor. Locate the map in Content Browser at Content/TechArtMuseum/SandboxGrid and open it.
  2. Press Play. Use the museum's existing WASD + mouse movement/look. The map keeps BP_FirstPersonGameMode, its pawn, controller and input setup.
  3. At the entry, use E on the E_Inspection_SmokeTest item to review the existing inspection flow. The assessment pairs themselves are observation displays: select their actors/assets in the editor for repairs. Skeletal examples use dedicated presentation Blueprints.
  4. Each gold review zone has an R trigger configured to toggle that bay's instructor answer. It references exactly one local answer actor; it does not use a world-wide exhibit tag. R/E physical input still needs human review.
  5. For repeatable editor views, find and pilot CAM_00_Overview, CAM_00_Entry or a bay's CAM_<ID>_Near. EXLOD and EXTEXMIP also have _Mid and _Far cameras and matching floor marks. Return to a common camera when comparing.

The EX24 lighting controls are in /Game/TechArtMuseum/SandboxGrid/Sequences/LS_EX24_LightSweep: two matched lights have the same eight-second lateral sweep, configured to loop in Play. Open the sequence in the editor to pause or scrub both lights together. For EXA/EX21, restart Play after a repair to reset both clips to time zero.

Repeat the build

From the workspace root in PowerShell:

& .\TechArtMuseumIntegration\Scripts\SandboxGrid\RunSandboxGrid.ps1 -Action Build
& .\TechArtMuseumIntegration\Scripts\SandboxGrid\RunSandboxGrid.ps1 -Action Validate

The runner uses UnrealEditor-Cmd.exe, -run=pythonscript, -unattended, -nop4, -nullrhi and the command-line Geometry Scripting plugin enablement. It does not require changing the project's permanent plugin configuration. The builder creates a fresh transient world and saves only the named sandbox map. Stable asset names and a fresh world prevent duplicate bays on reruns. Rebuilding reapplies configured faults and overwrites generated geometry; keep any instructor/student repairs in a separate copy first. Do not rebuild while this sandbox map is loaded or locked in another editor.

Source modules are BuildExhibitReviewGrid.py, lod_instancing.py, materials_textures.py and geometry_animation.py.

Evidence and limits

  • BuildReport.json is the current build inventory: actual asset paths, bay transforms, cameras, configured faults and saved scene structure. A successful build is not a visual test.
  • GeometryAnimationBuild.json and MaterialTextureAssets.json contain the source, topology, material graph and texture-control evidence.
  • Fresh-process validation and the rendered/Play report will be recorded under Saved/SandboxGrid/. Rendering and physical input are separate gates.
  • EXLOD has real 150,000 / 52,500 / 15,000-triangle render LODs in Correct and only 150,000-triangle LOD0 in Incorrect. Fresh-load checks confirm thresholds 1.00 / 0.50 / 0.30; automatic rendered switching is a separate review gate. Both copies disable Nanite to expose conventional LOD behavior. Forced-LOD witnesses supplement the automatic main pair.
  • EXINST proves one actor / one ISM / 64 instances versus 64 independent actors/components with equal transforms. This is structural evidence; engine auto-instancing can reduce individual draw submissions. No measured draw-call ratio or GPU speedup is claimed.
  • EXTEXMIP uses one generated 1024² source PNG. The mip-generation setting is the controlled difference. Temporal antialiasing can suppress shimmer; metadata alone cannot establish the visible symptom.

The editable EX20 OBJ files are extracted from the existing diagnostic meshes, not replacement geometry. Their original UVs are all zero, so these remain untextured topology exercises. See Geometry_README.md for centimeter/Z-up import and Reimport With New File instructions. The EXMAT-A OBJ/MTL sources use Maya Y-up centimeters; follow each source's header. No Maya round trip has been tested. EX29 is a material-coordinate repair with verified existing assets, not a newly authored Maya UV-shell source.

The existing SourceArtDepot/Library/animation/khronos-animated-morph-cube/Working/MorphCube_Workfile.mb is available for EX21, but its clean-machine open/export round trip remains unverified. The saved pair has identical base geometry, material and skeleton; Correct has thin and angle, Incorrect has neither, and the shared clip has varying curves with those names.

Scope and handoff

INSTRUCTOR_KEY.md contains the answers and exact repair contracts. Keep it and the answer actors out of a student handout/map until the intended reveal. Student-facing labels show objectives and observation cues separately from the instructor answers.

Niagara and VAT are deferred. The existing animation wing, source galleries, lab forks, project startup maps and interaction implementation are retained. Additional loop/skin-weight animation defects and skeletal E inspection are outside this sandbox's implemented scope.

No Perforce submit, sync, cleanup or broad reconcile is part of the build. Review only authored files in Content/TechArtMuseum/SandboxGrid/, Scripts/SandboxGrid/ and Docs/SandboxGrid/, plus explicitly reported guide updates. Saved/SandboxGrid/ contains validation evidence and previews; choose which evidence to retain rather than reconciling the entire Saved directory.
