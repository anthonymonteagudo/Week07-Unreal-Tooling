What the book changes in the review

The dot demo can now use a concrete book-inspired arrangement: two endpoints and a shared reference point C. Display A−C and B−C, then their normalized dot. This is a different experiment from the earlier A-to-B displacement tool. Move the reference point as well as the endpoints and ask students to explain the changed directions.

The rotation comparison can use the same marked wireframe object for matrix and quaternion results. The book's cube is useful, but add a marked vertex or directional pointer so cube symmetry does not hide a change. The gimbal reference on p. 123 provides an actual example of rings, an orientation arrow, and angle controls. These are source references for preparing project captures, not claims that our project already implements them.

Keep the full planned hierarchy, coordinate-space, and interpolation lesson. The supplied volume focuses on its four visualization tools. A text search for interpolation finds a passing mention on p. 74 and a glossary reference on p. 130; the inspected chapter sequence does not provide a worked lerp/slerp lesson. The live interpolation material remains supported by the instructor outline and separate references. The guided projection exercise is an original adaptation, not a copied book exercise.

Instructor clarifications before adapting examples

  1. Dot and facing (pp. 14–17): dot returns a scalar. With a unit projection axis it gives signed projection length; a projected vector needs a further multiplication by that axis. For normalized directions, ±1 means aligned/opposed, while positive/negative separates hemispheres relative to a chosen forward direction. Above/below is a different axis relationship.
  2. Quaternion representation (pp. 75–77): the constructor uses vector components followed by the scalar, while the worked tuple labels the scalar first. Both orderings can be valid; label them and do not copy numeric positions between them blindly. A point encoded as a pure quaternion for rotation has scalar part zero; that is distinct from affine homogeneous coordinates where a point uses w=1.
  3. Conjugate versus inverse (pp. 73–76, 90–93): conjugation equals inversion for a unit rotation quaternion. Validate or normalize the rotation quaternion as appropriate. A zero rotation axis needs a deliberate response.
  4. Y-rotation discrepancy (pp. 104 and 109): the printed matrix uses +sin at row 1, column 3 and −sin at row 3, column 1. The later GetPitch listing reverses those signs. Under the same column-vector convention these perform opposite rotations. This was checked in rendered pages, not inferred from missing extracted symbols. At +90°, applying the printed matrix to +X gives −Z; the later listing gives +Z. Choose a convention and test it explicitly before adaptation.
  5. Angle units (pp. 94, 98–99): the hand-built sine/cosine calculations here require radians. This is a property of the calculation/API, not a universal rule that every quaternion or matrix API accepts radians. Keep the degree/radian conversion visible at the input boundary.
  6. Matrix types (p. 103): the use of a 4×4 container for a 2D example reflects a library/type choice. It does not mean C# cannot represent 2×2 matrices. Explain the mathematical shape independently of its storage type.

These clarifications guide teaching and adaptation; this review does not certify the complete book code. The stated numerical cases in the expanded review remain the verification baseline.

Suggested reading selections

  • First review: pp. 13–17 for dot and pp. 43–45 for cross, accompanied by the clarifications above.
  • Rotation review: pp. 74–78 for axis-angle/quaternion rotation and pp. 97–105 for matrices and Euler angles.
  • Tool-building study: pp. 52–64 for reusable interaction support, pp. 78–94 for the quaternion visualizer, and pp. 106–123 for the Euler/gimbal visualizer.
