Technical Art course visuals

Locate the course root by finding Course/AGENTS.md and Course/Visuals/tokens.json in the current project. This skill's tracked source is Course/Skills/course-visuals/SKILL.md; its installed copy provides discovery. Read Course/Visuals/RULES.md for the asset conventions and manifest.json for existing files and intended uses. Do not search unrelated projects when this course is absent.

Start with the teaching job: identify a role, show a relationship, demonstrate an observable change, or provide actual software evidence. Reuse an existing asset when its meaning matches. Week 1's four lens badges retain their established names and colors. Artistic intent is a topic applied through those lenses, not an added fifth lens.

For icons, prefer the existing transparent PNG/SVG library. New simple symbols should extend its code-authored vector family, with PNGs rasterized from the master. Use an external icon library only after checking the exact source and reuse terms and making the new family visually compatible. Search results are candidates, not licenses. Preserve original attribution; do not assign a new license to existing course images with unknown provenance.

Use ImageGen when bespoke raster illustration adds teaching value. Provide approved course references and request genuine alpha transparency, consistent geometry, restrained palette, and no embedded labels. Verify the returned alpha, silhouette, and small-size readability. Do not represent generated Maya/Unreal interfaces, research figures, or plausible-looking asset failures as evidence. Transparent-looking checkerboards are not transparency. Do not repeatedly generate glyphs that can be drawn deterministically as vectors.

For diagrams, use the installed diagram-design skill when available, with the course profile in Course/Visuals/diagram-profile.md. Run the course profile installer when the machine lacks that profile. Keep the diagram-design package's global defaults unchanged. The user has selected Week 1 continuity; do not ask them to select an unrelated default style. Read the chosen diagram type's guidance and apply the course's slide-sized labels and font fallback disclosure.

Keep editable SVG plus a slide PNG. Name nodes for actual entities and label ambiguous arrows. Separate authoring relationships from rendering execution. In Week 2, keep GPU implementation closed, distinguish geometric normals from normal-map data, and preserve the Maya → exchange → UE → revision/reimport check. A schematic supports a demonstration; it does not certify a museum asset.

The instructor's diagram defaults are transparent canvas, concise labels, bold arrows, clear sequence, and real visual context. Apply these to new diagrams and revisions. Use short noun phrases (usually 1–4 words) and brief relationship verbs; put sentences, caveats, questions, citations, and teaching explanations in the review HTML and read-aloud notes. Remove slide-like title furniture and text-filled boxes. Preserve meaningful labels such as optional, parent, and UV channel even when shortening.

For concrete asset topics, build around actual cropped textures, UV layouts, Maya/Unreal controls, meshes, or observed results. Search existing course/source images first. Prefer related views of the same asset. Never replace obtainable real evidence with generic icons or generated UI. For a mixed-source overview, label separate examples visibly and explain their relationship in HTML; do not imply a matched before/after or continuous capture. Preserve original pixel contents, aspect ratio, relevant control context, full source, crop bounds, credit, and known version. If source resolution is small, use it for recognition and provide a larger original for inspection; do not invent detail with generative upscaling.

Export true alpha PNGs with no full-canvas fill, white matte, or baked checkerboard. Real screenshot rectangles may retain their native opaque backgrounds. Use strong arrowheads and approximately 5–6 logical-pixel primary connectors at 1280×720; route cleanly around images and labels. Give optional paths a distinct, explained style. Inspect on white and the Week 2 slide background, and supply an alternate ink treatment if a dark-background version is required. Do not claim a transparent asset is readable on every background. Verify alpha and the actual crops, as well as the graph's conceptual accuracy.

Use the course review format: actual current slide beside proposed change, a direct asset preview/download, intended slide and concept, read-aloud notes, and a separate rationale. For optional depth, put a named Explore further destination on the proposed slide and in notes. Required lab prerequisites stay live. Prepared Markdown documents should open through the course reader views, with the original source offered separately; do not present a repository chrome page as a finished teaching handout.

After creating assets, rebuild the visual gallery, run alpha/asset verification, and inspect representative images at presentation and small-icon sizes on light and dark backgrounds. Check diagram text and connectors visually. Use permitted rendering tools; do not bypass a browser policy restriction. Report browser checks separately from SVG/PNG inspection. Update the manifest and the HTML review with the asset's specific use. Shelf only authorized course files; do not edit a PowerPoint when the current request is only for a review.
