One arm, many mathematical questions

Propose a minimal shoulder/elbow/wrist joint hierarchy with a visibly asymmetric hand proxy. Start with simple FK, visible local axes, world-position readouts, and a target locator. Prepare the rig and drawing system before class. Skinning, production controls, IK/FK switching, and full rig architecture are not prerequisite build tasks for this math session.

Use the same geometry across topics:

Topic Visible question in Maya Readout or check
Displacement and magnitude Where is the elbow relative to the shoulder? E−S and segment length.
Velocity How far did the wrist move between two times? Displacement/elapsed seconds; label it average velocity.
Dot How aligned are consecutive segments? normalize(E−S)·normalize(W−E), with arrow directions visible.
Cross What is perpendicular to the bend plane? (E−S)×(W−E), including raw magnitude.
Coordinate spaces Why can a child keep its local offset while moving in world space? Parent/world position comparison.
Matrices and hierarchy How does shoulder motion affect wrist placement? Child-local × parent-world and the resulting world axes.
Euler/quaternion How do representations and operation order affect the marked hand? Same start/end orientation and explicit rotation order.
Interpolation What path does the wrist/hand take between endpoints? Fixed endpoint and t-driven position/orientation comparisons.
Projection lab Where does the elbow depart from the shoulder–wrist line? Projection H, residual b, validity feedback.

Reproducible bent-arm preset

Use world positions in centimeters: S=(0,0,0), E=(3,4,0), W=(6,0,0). Each segment length is 5. Consecutive normalized segment dot is −0.28. Their angle is about 106.26°; the interior elbow angle uses E-to-S and E-to-W and is about 73.74°. Do not label those two quantities interchangeably.

The raw cross is (0,0,−24), perpendicular to both segments. With a straight limb it becomes zero; normalization cannot recover a reliable bend-plane direction. This geometric degeneracy is different from Euler gimbal lock.

For the guided projection helper, u=normalize(W−S), H=S+dot(E−S,u)u, b=E−H. The preset yields H=(3,0,0), b=(0,4,0). A display/control candidate E+2 normalize(b) lies at (3,6,0). This point lies toward the elbow bend. The plane normal is a different quantity and must not be used as if it were the pole-control position.

If a prepared rotate-plane IK example is included, use Maya's pole-vector mechanism to show the bend-plane relationship. The helper calculation is a teaching diagnostic, not a complete no-flip solver. At a straight arm or coincident S/W, show a declared invalid state; a production rig needs a deliberate fallback/reference plane.

Maya matrix convention and joint-specific context

The live slides now use p_world=p_local M_world, matching Autodesk's documented point convention. Compose a clean child hierarchy as M_child_world=M_child_local M_parent_world. For the isolated order example, pSRT applies scale, rotation, then translation. A source written with columns uses transposed matrices and the opposite written order for the same mapping.

Keep the first experiment clean: plain transforms for scale/pivot illustrations; unit joint scales; ordinary transform inheritance; identity offsetParentMatrix; no hidden constraints or offsets. A joint's local matrix contains orientation and compensation factors beyond animated rotate. Inspect local axes and jointOrient alongside rotate. Do not claim zero rotate values imply alignment with world axes, and do not imply generic SRT is the full joint formula.

Optional dot material graph

Teaching purpose: turn the same directional comparison into a visible material mask. Use m=max(dot(N_unit,L_unit),0), with N and L in the same declared space. L is a chosen direction, not an automatically available scene-light vector. This is a diagnostic mask, not a full physically based lighting model.

Maya Hypershade candidate

  1. Use samplerInfo.normalCamera as the normal input and a nonzero camera-space direction parameter for L.
  2. Normalize the two inputs explicitly using vectorProduct in No Operation mode with Normalize Output on. This makes normalization visible to students.
  3. Connect them to vectorProduct in Dot Product mode, with Normalize Output off. Use outputX as the scalar; Maya repeats the dot in its three output channels.
  4. Clamp to [0,1], replicate the scalar into color, and connect to a diagnostic surfaceShader.outColor preview where supported.
  5. Keep the raw dot readout separate. Aligned, perpendicular, and opposed tests should produce raw 1,0,−1 and clamped 1,0,0.

The chosen camera-space direction is camera-relative. For a world-fixed mask, first put both inputs in world space with an appropriate normal transform; do not silently mix normalCamera with a world direction. Renderer and viewport support for the proposed utility network must be tested before classroom capture.

Unreal alternative

Use a world-space normal and a declared world-space vector parameter, Normalize each, then DotProduct and Saturate. Present through an Unlit Emissive output to isolate the mask. Preserve the same three numerical cases. This is a proposed cross-application comparison, not a reason to move the main lecture out of Maya.

Optional cross material graph

Teaching purpose: reconstruct a perpendicular surface direction from two tangent directions. This is a closer geometric analogue to the arm bend-plane normal than a generic “cross makes colors” demonstration.

Maya Hypershade candidate

  1. Use samplerInfo.tangentUCamera and tangentVCamera, both in camera space.
  2. Feed them to vectorProduct in Cross Product mode with Normalize Output off so raw magnitude remains inspectable.
  3. Detect a near-zero magnitude before normalizing. Show an invalid-state color for degenerate inputs rather than presenting an arbitrary normal.
  4. Normalize the valid result and display 0.5n+0.5 through a diagnostic color output.
  5. Swap input order. The perpendicular direction reverses; its display color changes accordingly.

Use a simple nondegenerate parameterized surface first. Tangent parameterization and orientation determine the sign. This preview need not match a renderer's smoothed or perturbed shading normal in all cases. The encoded display color is not a tangent-space normal-map value ready for a Normal socket; it is a visualization of a camera-space vector.

Unreal alternative

Use two explicit nonparallel same-space tangent vector inputs in CrossProduct, then normalize a valid result, multiply by 0.5 and add 0.5, and preview in Unlit Emissive. If using actual mesh or derivative tangents later, label the source and space. A full tangent-frame reconstruction must account for handedness and mirrored UVs.
