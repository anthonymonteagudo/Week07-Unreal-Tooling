Materials, shaders, and textures: a Week 2 teaching guide

Prepared for Prof. Monteagudo, September 8, 2026. Fundamentals illustrated in Unreal Engine 5.7, as identified by this project's .uproject file.

This is an instructor guide and an expanded lesson outline. The core explanations can become student reading or speaker notes. Sections marked Deeper connection provide optional depth. The demonstrations and assessment prompts are recommendations, not changes to the course requirements or museum assets.

1. The learning target

By the end of this lesson, a beginner should be able to point to a mesh, its assigned Material or Material Instance, a texture, and the connection that gives that texture meaning. They should be able to predict one visible change and propose a test when the result differs from the intention.

A more experienced student should be able to distinguish stored data from interpretation, trace an override back to its owner, and explain why a plausible-looking result does not prove a correct pipeline.

The organizing question is:

Where did this surface value come from, how was it interpreted, and what used it?

Start with the shader, as a brief explanation of the underlying mechanism. Move immediately into the Material as the place students author and inspect that mechanism in UE. Introduce texture inputs once students understand what a surface input does.

The core route is Sections 2–8, followed by one worked example from Section 11. Sections 9–10 explain the wider pipeline. The remaining sections support preparation, assessment, and deeper reading. This full guide is a reference, not a script to deliver in one sitting.

2. A shader is a program

Core explanation. A GPU is a processor designed to perform many operations in parallel. A shader is a program it executes. For this lesson, concentrate on programs involved in drawing objects and calculating surface appearance.

Suppose we draw a simple ball. Knowing the ball's shape does not tell us whether it looks like chalk, polished plastic, or metal. The rendering system also needs instructions and surface data. Shader programs perform parts of that work.

The ball's mesh is its geometric representation, commonly connected triangles with positions and other attributes. Rendering is the process of computing an image from a scene. These terms give us a way to distinguish the object's shape, its surface setup, and the resulting picture.

Say aloud: “The GPU does the work. Shader programs provide instructions for that work. In Unreal, we can author much of an object's surface behavior through a visual Material graph.”

UE bridge. Material nodes become shader code, which is compiled for the target platform. Students can author useful Materials without writing HLSL, Unreal's shader-language foundation. Epic: Essential Material Concepts

Correction to the sketch. Label the relationship GPU executes shader programs. The GPU does not define a Material's artistic controls. The engine's material system and the graph author define them.

Deeper connection. Shader and shading are related words, but they are not interchangeable. Shading concerns appearance calculations. Shader programs can also transform vertices, move a surface, or perform other GPU computation. One UE Material can require multiple compiled programs for different passes, mesh types, or feature choices. “One Material equals one pixel program that writes the final screen color” is too restrictive. Epic: Graphics Programming Overview

Lab nugget. The Grow exhibit is a later example of why shaders can affect position as well as color. Mention this possibility in one sentence. Vertex displacement, its bounds, and its geometry requirements can wait.

3. A Material describes the surface in Unreal

Core explanation. A UE Material is an asset containing a graph and settings that describe how a surface should be rendered. Its graph calculates values for inputs such as Base Color and Roughness.

Use one sphere or one of the Bricks meshes with a deliberately small Material. Set a constant color, Metallic to 0, and Roughness to 0.6. Keep the light and camera fixed. The object already has a working Material without an image texture.

Say aloud: “This input needs a value. We can supply one number, a color, or the result of another operation. Textures are one way to supply those values.”

Nodes are operations, and wires carry values. A Multiply node multiplies its inputs. A Texture Sample reads texture data. These connections describe data dependencies, rather than a Blueprint-style sequence of gameplay events. The graph's visible arrangement is an authoring aid, and the compiler can reorganize its work.

Three settings establish the context: Material Domain identifies the intended use, Blend Mode determines coverage/blending behavior, and Shading Model determines the surface-response model. For the initial exercise, use an ordinary Surface, Opaque, Default Lit setup. Available inputs depend on that context. Epic: Material Properties

Deeper connection. The graph generally supplies surface attributes to engine rendering code. Connecting a Base Color is not the same as writing the final displayed RGB value. Lighting, visibility, exposure, and display processing still affect the image.

Check understanding: “If I remove all image textures but keep a blue color and a roughness value, can this object still render?” Expected: yes. A texture is useful when we need particular data or spatial variation, rather than as a requirement for every surface.

4. Parameters and Material Instances make variation manageable

Core explanation. A parameter is a named input that the Material author makes adjustable. A Material Instance inherits from a parent and can override exposed parameters. A constant roughness of 0.6 is fixed in the graph. A Scalar Parameter named SurfaceRoughness allows instances to supply different values.

Create M_SurfaceStudy and two instances, MI_SurfaceStudy_Smooth and MI_SurfaceStudy_Rough. Assign them to identical meshes. Change only their roughness values. The surface logic is shared, while the settings differ. These are proposed teaching assets, not existing project assets.

Use these terms carefully:

Term Meaning in this lesson
Material input A destination such as Roughness or Base Color
Parameter A named adjustable value or resource reference
Material Instance An asset inheriting a parent's setup and overriding selected parameters
Texture parameter An exposed choice of texture resource
Component material override A different Material or instance assigned to a slot on one placed component

An input does not automatically become an exposed parameter. Naming and exposing parameters is an authoring decision.

Deeper connection. Ordinary scalar, vector, and compatible texture changes can reuse compiled logic. Static switches select compiled alternatives and can require shader permutations. Material instancing also differs from mesh instancing: creating Material Instances does not itself guarantee fewer draw calls. Epic: Material Instances

Lab nugget. If the preview looks correct but one placed object differs, first trace the actual assignment and overrides. The museum's painting exhibits share a mesh but use different component Materials. Their identity and appearance cannot be reconstructed reliably from mesh identity alone. This is documented in the interaction migration plan.

5. A texture is data we can sample

Core explanation. For this lesson, an image texture is a grid of stored values. Each element is a texel. A screen image also has pixels, but a texel and a screen pixel are not the same thing. A texture may cover many pixels up close and contribute to only a few pixels at a distance.

A Texture Asset, a Texture Sample node, and a Material input have different roles:

Part Role Example
Texture Asset Stores source content and settings used to prepare/interpret it A grayscale image and its import settings
Texture Sample Reads the texture at supplied coordinates using sampling rules Read the red channel at a surface location
Material input Gives the resulting value its role in the surface model Use that number as Roughness

The conceptual hinge: Replace a constant roughness with a simple two-region texture. Keep Base Color unchanged. Ask students to predict where the reflection will appear sharper.

Say: “A constant gives the same roughness everywhere. A map lets roughness vary across the surface.” A black-to-white preview helps us inspect the numbers. It does not mean the object must become black and white.

Textures can contain color, surface directions, masks, or other data. The graph and resource interpretation determine how the values are used. A filename such as _Roughness communicates intent to people and may guide an importer, but it does not establish a universal rule in every shader. Khronos: glTF material data

Deeper connection. Procedural functions can produce spatial variation without an image lookup. In some rendering literature, “texture” includes these functions and even constant-valued functions. In this UE lesson, say image texture when you specifically mean an imported image asset. This lets students read broader resources without treating their terminology as contradictory. PBRT: Textures and Materials

Lab nugget. Piet, Cat, Grid, and Line can introduce the idea of values calculated from coordinates. Their complete construction and derivative-based filtering are optional extensions.

6. UVs provide addresses, and sampling reads the data

Core explanation. U and V are coordinates used to locate values in a 2D texture. Think of them as addresses. A mesh commonly stores UV coordinates alongside its vertex data. During rendering, coordinates are interpolated across triangles so different surface locations can read different parts of an image.

The familiar 0–1 square covers one full image in each direction. UVs may extend outside it. Addressing rules such as wrap or clamp determine what a lookup does beyond the image boundary.

Show: A numbered checker on a flat panel and then on a Bricks mesh. Identify one number in the image and its location on the surface. Change the UV tiling multiplier while holding the mesh, image, and light constant. With wrapping, greater UV repetition makes the repeated pattern smaller on that fixed surface.

Say aloud: “The image stores the values. The coordinates tell us where to read. Sampling determines how nearby stored values contribute.”

The first statement can use the address analogy. Then qualify it: a filtered lookup can combine several texels, and can use different mip levels. It is not always an exact read of one image pixel. Gambetta: Textures

Trace two locations: At location A, the UVs lead to a roughness sample of 0.2. At location B, they lead to 0.8. Both locations use the same blue Base Color and the same Material logic. The differing roughness values change the local reflection behavior. This is an idealized example with no additional remapping.

Lab nugget. Bricks and EX29 ask students to distinguish a texture problem from a mapping problem. If labels are mirrored, increasing resolution cannot fix their orientation. If brick size differs, inspect coordinate choice, UV scale, and world scale before repainting the texture.

Deeper connection. UVs are one possible coordinate source. World position, object position, or generated coordinates can drive a material. Scaling an object can affect visible pattern size differently depending on that choice. “Every material needs unwrapped UVs” would conceal the reason these alternatives exist.

7. The surface inputs students actually need

The following explanations assume a conventional UE metal/roughness surface workflow. They deliberately avoid teaching every available input at once. Introduce Base Color and Roughness first, then Metallic and Normal, then coverage when showing Alpha Leaf.

Input Beginner explanation Useful precision
Base Color The surface's underlying color input In the metal/roughness model, it describes diffuse color for nonmetals and reflection color for metals. It is not a photograph of the final lit object.
Roughness How microscopically smooth or rough the surface behaves Low values give sharper reflections; higher values broaden them. It is not a height map.
Metallic Whether the modeled surface behaves like metal or nonmetal Use 0 for a pure nonmetal region and 1 for exposed metal. Intermediate values can represent mixtures or filtered boundaries. It is not a general shininess slider.
Normal Surface direction used for shading A normal map changes the shading direction, producing apparent detail without moving the mesh's vertices.
Emissive Color The surface's emitted contribution A bright appearance or bloom does not by itself prove useful illumination of nearby objects. That depends on rendering features and settings.
Opacity Mask Which samples survive a cutoff in a Masked material Useful for leaf cutouts. It does not remove the source mesh's triangles or rewrite its collision.
Opacity The opacity input for supported translucent shading paths It requires an appropriate Material setup. An image having alpha does not activate translucency.

Sources for the input model: Epic: Physically Based Materials, Epic: Material Inputs, UE 5.7.

Show: Two nonmetal surfaces with the same color and different roughness. Then keep roughness fixed and change Metallic. Ask students to name which change affects reflection spread and which changes the surface model.

Deeper connection. A normal is a direction. Roughness describes unresolved microstructure affecting how reflection spreads. A bump or normal map represents direction variation across the surface at a different scale. Adjusting one to compensate for an error in the other can match a single view while failing when the light moves.

For ordinary nonmetals, leave the conventional UE Specular input at its default initially. Its reflectance role is more specific than the everyday word “shiny.” More advanced readers should explore Fresnel: reflectance also changes with viewing angle. Adobe: PBR Guide Part 1

8. Data needs the correct interpretation

Core explanation. Two texture assets can begin with identical source pixels and still supply different values during rendering. Import settings, color decoding, compression, channel selection, and sampler behavior all matter.

Teach three separate questions:

  1. What does this channel represent?
  2. What transformation happens when it is read?
  3. Which input receives the result?

Color versus numeric data

Color images commonly store RGB in sRGB encoding. Shading calculations generally require linear values, so the rendering system decodes that color data. Roughness and metallic masks usually represent numbers directly and should follow their documented linear-data interpretation.

A useful numeric example for the instructor: An encoded sRGB RGB-channel value of 0.5 decodes to approximately 0.214 in linear space. A roughness value intended as 0.5 should remain 0.5. Applying color decoding to it changes the quantity. This example ignores quantization and compression so the mechanism is clear. It is not a rule to apply to every texture channel, and ordinary sRGB decoding does not apply to alpha. W3C: sRGB conversion code

Say aloud: “The same stored number can mean a color code or a measurement-like value. We need to tell the system which interpretation is intended.”

Lab nugget, EX23: Compare the correct and incorrect data textures without changing the light or Base Color. Inspect the documented channel and decoding settings. Avoid restoring the appearance by changing a roughness multiplier before establishing whether the input was decoded correctly.

Channel meaning

R, G, and B are channel names. They do not force the stored data to be visible color. Packed textures can place independent quantities in different channels. Packing conventions must be read from the asset's export contract. For example, core glTF metallic/roughness data uses G for roughness and B for metallic. That is a format-specific rule, not a universal Unreal rule. Khronos: Metallic-Roughness Material

Normal maps

A tangent-space normal map describes directions relative to a basis attached to the surface. The familiar blue-purple image is a visualization of encoded components. It is not blue surface paint.

Lab nugget, EX24: Check normal-map compression, linear interpretation, the Material's sample type, and the expected normal convention. Keep the first demonstration to one controlled fault. A green-channel inversion is an alternative diagnosis to establish from evidence, not a universal fix for every shading artifact. Move the light to verify the result from multiple directions.

Deeper connection. Mesh normals, tangents, UV seams, and triangulation can affect the basis used to interpret a tangent-space normal map. A normal map should not be expected to repair a missing face or arbitrarily changed baked geometry. Compare the mesh with a plain diagnostic Material when geometry and shading-data hypotheses overlap. PBRT: Material Interface and Implementations

UE exposes channel views, compression, dimensions, and mip information in the Texture Asset Editor. These are evidence about the imported asset, alongside the source image. Epic: Texture Asset Editor, UE 5.7

9. The material has to reach the intended surface

Core explanation. A mesh can have multiple material slots, with different mesh sections using different slots. The mesh asset supplies default assignments. A placed mesh component can override an assignment for that particular object. The selected assignment may itself be a Material Instance with parameter overrides.

Trace a suspicious surface in this order:

  1. Select the actual component rendering the surface.
  2. Identify its mesh section/material slot.
  3. Inspect any component override and the mesh's default assignment.
  4. Open the Material or instance that is actually assigned.
  5. For an instance, identify its parent and active overrides.
  6. Follow the relevant input to its texture, value, coordinates, and interpretation.

Lab nugget, EXMAT: The source mesh can export the wrong section assignment, or Unreal can assign the wrong Material. Find which handoff first disagrees with the intended contract. A source assignment error belongs in the source workflow. A component override error belongs on that component.

Maya's full shading network should not be assumed to reproduce automatically in UE through FBX. FBX material import supports a subset of material information. Verify slot identity, texture references, and the engine Material setup after the handoff. Epic: FBX Material Pipeline, UE 5.7

Deeper connection. A resource is often shared by many users. Editing a parent or a Texture Asset can affect multiple objects. Reassigning one component or changing one instance has a different scope. In the museum, use the provided editable duplicates and preserve Correct as the control.

10. Authoring, rendering, and the final image

Use the diagrams in the companion diagram source. Each arrow has a verb. The first diagram shows preparation and assignment. The second shows how data contributes during rendering. Neither implies that a texture is produced by a Material Instance or that the GPU invents shader instructions.

An illustrated overview with real UE screenshots follows the revised visual layout. It shows actual texture-sample previews, a Material graph, settings, generated HLSL, instance controls, material assignment, and a rendered preview. Image provenance and teaching qualifications distinguish the walnut-floor examples from the separate instance UI example.

Authoring and preparation: Model geometry and author its attributes. Create or acquire texture content. Import with the intended settings. Author a Material graph. Expose the useful parameters. Create instances where variation helps. Assign the Material or instance to the mesh component. The engine builds shader programs and usable texture resources from these assets.

Rendering: The engine prepares the relevant mesh data, shader programs, parameters, texture resources, and scene information. The GPU executes rendering work. Coordinates locate texture data. Material calculations produce surface attributes or pass outputs. Lighting and visibility calculations contribute to the image. Exposure, tone mapping, and display conversion affect the displayed result.

In a typical deferred opaque path, surface attributes can be written into intermediate buffers called the GBuffer, with lighting computed in later passes. The exact stages and order depend on the rendering path. The guide's diagram is a dependency overview, not a GPU command trace or a claim that all surfaces use the same path. Epic: Graphics Programming Overview

Deeper connection: where the surface locations come from. In a conventional rasterized path, vertices are transformed toward camera/screen space, triangles are clipped and rasterized into covered samples, and interpolated attributes feed shading. Depth and coverage determine which contributions survive or combine. UE also has rendering paths that do not fit one simple triangle/pixel sequence, so this belongs in an optional explanation rather than the first definition. LearnOpenGL: Shaders

Lab nugget: A surface that appears wrong in one environment may be affected by light direction, reflections, exposure, or viewing angle. Establish a comparable scene before changing asset data. A correct-looking screenshot proves less than a controlled test across relevant conditions.

Distance matters. Mips provide prefiltered representations for different sampling footprints. Filtering combines appropriate samples. Streaming controls which resources or mip levels are available. Compression changes storage representation and can introduce error. Mesh LOD changes geometry. These mechanisms cooperate, but they are separate causes to test.

Use EXLOD as a bridge: if a Material changes only when a mesh switches LOD, inspect the section/material mapping and UVs for that LOD as well as the texture. For a texture that shimmers as it recedes, investigate sampling and high-frequency detail. A distance-dependent symptom is evidence, not a diagnosis. LearnOpenGL: Textures

11. A worked demonstration: the same surface, different roughness

Use a separate teaching copy and a simple mesh before approaching the assessed museum specimen. Prepare the assets before class, with the graph arranged to show only the inputs under discussion. This avoids spending the explanation on file creation and menu searches.

Preparation: One mesh with readable UVs, fixed scale and camera, a broad light/reflection source that makes roughness visible, and a consistent exposure. Create the proposed M_SurfaceStudy and the two instances from Section 4. Prepare a simple linear grayscale texture with regions near 0.2 and 0.8. Put its intended channel and interpretation in the asset notes. Verify that the comparison is visible in the actual classroom rendering setup.

Step Instructor action Student prediction or explanation
1 Assign a constant blue, nonmetal Material with Roughness 0.6. Identify the mesh, Material, and visible surface. Can it work without an image texture?
2 Change only roughness to 0.2, then 0.8. Predict which produces a sharper reflection. Explain what remained unchanged.
3 Show two instances of the same parent. Change one override. Predict whether both copies change. Point to the scope of this edit.
4 Replace constant roughness with the documented channel of the two-region image. Predict where reflections sharpen. Explain why the object remains blue.
5 Trace a surface location through its UVs to the sample and Roughness input. Identify the source value and its destination.
6 Change only the UV tiling parameter, with wrap addressing. Predict the pattern scale. Did the mesh acquire more polygons?
7 Show a prepared duplicate with the wrong color/data interpretation. Describe the symptom before naming a cause. Suggest a confirming comparison.
8 Restore the correct interpretation. Compare under the same conditions, then move the light. Explain why the repair is stronger evidence than compensating with a new roughness multiplier.
9 Recheck Base Color, assignment, and the unedited control. Record the primary verification and one unaffected property.

The wrong-interpretation variant must remain a valid, compilable setup. If the chosen UE settings produce a sampler-type error, treat that as explicit evidence or prepare a compatible variant that isolates numeric decoding. Do not improvise several simultaneous setting changes in front of the class and call the result one controlled fault.

Instructor narration for the repair: “Our observation is that the reflection is sharper in this region. We know the source image and scene are the same. Now we compare how the texture is read. We found a disagreement with the data's intended meaning. After restoring that setting, the reflection matches the control from more than one light direction, while the blue color remains unchanged.”

Optional transfer, Alpha Leaf: Show alpha once as visible grayscale data, then as the input controlling a Masked surface. Keep the source geometry visible in wireframe. Ask what changed about coverage and what did not change about geometry or collision. This generalizes the lesson that a value's destination determines its role.

Optional transfer, procedural pattern: Supply a simple coordinate-derived mask in place of the image mask. The visible division can be similar while its data source differs. Ask which parts of the pipeline are shared. Avoid teaching the full Cat or Grid implementation here.

12. A diagnosis method students can reuse

Use a neutral description first: “The leaf shows a rectangle,” “the labels are mirrored,” or “the reflection broadens differently.” Then form at least two plausible explanations and choose a test that separates them.

Observation Plausible layers to distinguish Useful test
Correct preview, wrong placed object Assignment, component override, instance values, scene context Open the actually assigned asset and compare under the same scene conditions.
Pattern has wrong orientation UV shell, coordinate channel, graph coordinate transform Apply the known numbered checker and compare coordinates before editing image content.
Reflection looks unusually sharp Roughness source, decoding, channel routing, override, lighting Compare input values and interpretation with the control while holding the scene fixed.
Fine relief responds incorrectly to light Normal import/decoding, tangent convention, mesh basis Compare normal-map settings and move the light. Check a plain Material if geometry is also suspect.
Leaf shows its rectangular card Assigned Material, alpha/mask connection, blend mode, cutoff Inspect mask data and the actual Material's coverage setup.
Surface changes at distance Mesh LOD, material sections, mips, streaming, filtering Observe which state changes at the artifact's onset. Compare active LOD and available texture detail.
An edit changes many objects Shared parent, shared texture, shared instance Trace the references and decide which asset owns the intended variation.

These are starting hypotheses, not a deterministic symptom-to-cause lookup. Change one controlled variable when possible. Validate the intended effect and a property that should stay stable. If the source must change, repeat the handoff to prove that the repair survives it.

A stronger advanced challenge: Give a learner a visually acceptable “repair” made by compensating for a wrongly decoded roughness map. Ask them to design a test that exposes the mismatch. For example, compare several known source values or vary the mask. Matching one sample or one view does not establish that the transfer function is correct.

14. What to assess, and how to support mixed experience

Use one worked example, one partly completed example, and then one new problem. Ask students to explain decisions, not just identify a node. Pair the diagram with its corresponding live control or surface change. Return to the same relationships in a short recall task next week. These choices apply the IES recommendations on examples, graphics with explanations, abstract/concrete connections, explanatory questions, and retrieval. The exact lesson sequence here is an instructional proposal, not a research-tested materials curriculum. IES: Organizing Instruction and Study

Check Expected reasoning
Can a Material work without image textures? Yes. Constants and procedural calculations can supply inputs.
Why can a gray image change reflections without making an object gray? Its values are supplying a property such as Roughness rather than Base Color.
Why can identical pixels produce different results? Interpretation, routing, parameters, coordinates, assignments, or scene context can differ.
Does a normal map repair missing polygons? No. It supplies shading directions; the missing geometry still needs its own repair.
Does an alpha channel automatically create a leaf cutout? No. The assigned Material must read it and use appropriate coverage behavior.
Does changing one instance necessarily change every object using the parent? No. Identify the scope and which objects use that particular instance.
Why can a source image look fine while the UE asset is wrong? The imported asset has settings and processing beyond the source pixels.
What makes a repair convincing? A diagnosed cause, a controlled change, repeatable verification, and a checked unaffected property.

For beginners, provide the diagram and ask them to follow one input. For more experienced students, remove the labels or introduce two plausible causes. Offer an advanced question about shared resources or compensating errors rather than forcing the entire class through extra implementation detail.

An optional formative rubric can score each dimension 0–2: trace the relevant data, distinguish competing causes, and verify the result. A successful click sequence alone does not demonstrate all three. This rubric is a suggestion, not an alteration to the lab's grading requirements.

15. Short glossary

Term Working definition
GPU Processor executing graphics and other parallel computation
Mesh Connected geometric elements, commonly triangles, with positions and other attributes
Rendering Computing an image from scene data
Shader program Instructions executed on the GPU
Shading model Rules approximating how a surface responds to light
Material UE asset describing surface logic and rendering settings
Material Instance A child setup inheriting from a parent and overriding exposed parameters
Scalar One numerical value, such as a roughness value
Vector A group of numerical components, such as a direction or RGB color
Parameter A named adjustable input
Texture Asset Texture content plus engine asset settings
Texel An element in a texture
Pixel An element in an image such as the rendered output
UV Coordinates commonly used to address 2D texture data
Texture sample A lookup that returns texture values using coordinates and sampling rules
Mask Data used to select, weight, or exclude something
Normal A direction describing surface orientation for geometric or shading purposes
Tangent space A local coordinate basis attached to the surface
Mip One level in a hierarchy of filtered texture representations
Material slot A mesh assignment location used by one or more mesh sections
Component override A replacement assignment or setting on a particular placed component
Compile Translate authored instructions into executable form for a target
