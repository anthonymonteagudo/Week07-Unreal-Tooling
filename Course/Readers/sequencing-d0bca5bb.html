Foundation sequence assessment — updated 13 October 2026

Main demo: Material Setup → VFX Placement, using the canonical route. The numbered prop checkpoints below are optional foundations. Their stable IDs are retained; they do not number the main demo or the slides.

Why this order

Week 3 already introduced values, collections, loops, functions and an asset report before host-specific operations. Steps 01–04 reactivate those ideas with Actor-shaped dictionaries. They can be compressed into a recap if students retain the Week 3 material. Keep scope selection explicit: a mixed selection is a common reason a seemingly simple batch operation becomes dangerous or confusing.

Steps 05–06 separate a report (what is wrong), a plan (what we propose to change), and application (what changes). Students can inspect each value and use VS Code breakpoints without needing an editor session. A missing mesh deliberately survives the rename operation: a successful fix is not proof that everything is valid.

Step 07 replaces repeated teaching functions with the project's tested pure rules. It adds placement and fixture IDs, then makes the boundary with Unreal visible. Step 08 is where selection, Actor/Component/asset distinctions, transactions and manual reload belong when the slides and the live demo are ready.

Differences worth discussing

  • Step 02 filters mixed data and reports exclusions. The live adapter deliberately rejects mixed selections before applying changes. Filtering is an introductory exercise, not a promise of identical production behavior.
  • Steps 03–06 derive names from trusted sample kind values. Production rules map known fixture IDs to kinds and validate IDs, paths and coordinates.
  • Step 06 checks the proposed rename list against a fresh list. It is an in-memory exercise, not full scene concurrency protection. The editor adapter also checks world, selection, full states, collisions and editor mode.
  • A deep copy is not an Unreal transaction. Editor Undo must be taught separately.
  • Production plans include all selected records, even already-correct ones. The introductory rename plan lists only changes. Inspect this difference in Step 07.
