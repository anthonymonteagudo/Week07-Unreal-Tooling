Before students use the workspace

  • Open the practice runner on the teaching machine when convenient and confirm the PRACTICE MODE header. Verify Qt setup using the existing UI dependency guide.
  • Perform each student task exactly as written. Expect one material instance and three effects. Repeat the preview to demonstrate overwrite/duplicate rejection.
  • Confirm Reset practice data resets both operations. Fields retain their values.
  • Test keyboard-only operation: Tab/Shift+Tab, combo selection, spin controls, Preview and Apply shortcuts, warning acknowledgement. Verify focus is visible.
  • Check the UI at classroom projection resolution and Windows scaling settings. At smaller widths, the table scrolls; action buttons must remain accessible.
  • Use the student guide for instructions; keep implementation-status documents and preset configuration in the instructor preparation material.

Canonical presentation sequence

Follow demo beats D1–D6, including the compatibility and reset boundaries. The principles below support that route; they are not a second sequence.

  1. Show the repetitive task: texture assignment, then placing an effect at markers.
  2. Ask students to predict what each operation will change and what stays shared.
  3. Run Choose → Preview → Apply → Check, pointing to the scope count and rows.
  4. Introduce one deliberate problem: duplicate output name or repeated markers. Ask students to read the message and recover before explaining the implementation.
  5. Compare UI quality using the task: can a new user identify the inputs, affected objects, next action and recovery? A consistent color scheme is only one part.
  6. Read the code in the student guide's order: inputs → rules → presentation → UI events → Unreal boundary. Revisit the preview after seeing the implementation.

No timings, slide numbers or assessment requirements are assigned by this draft. The UI stages now use Material Setup and VFX Placement themselves. Use the UI progression to compare the same task across functional, guided and refined presentations. Use Scripts/assistants.py --stage N and its matching stage capture set.

Consistency contract for the future native widget

Reuse workflow_presentation.describe_plan() (also returned by the native bridge) for counts, rows and action labels. Keep the same terms and four-step workflow. On input changes clear the plan; on warnings require acknowledgement; on completion show a result; on failure give a recovery action. Preserve the distinction between practice data, actual Unreal operations and performance measurement. This keeps student tasks stable when the presentation changes from PySide to an Unreal tab.
