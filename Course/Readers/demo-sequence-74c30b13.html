Updated 13 October 2026. This is the demo project's rehearsal order and capture map. D1–D6 identify demonstration beats, not slide numbers. No deck was edited, timings assigned or lab requirements finalized by this cleanup.

Rehearse the primary route

From the project root, manually run:

./.venv/Scripts/python.exe Scripts/assistants.py

Keep PRACTICE MODE visible. The sample supplies textures, a crate and three markers; clicking in Unreal does not change these inputs. Begin with fresh practice data, name MI_Crate_Demo, slot 0, and effect scale 1.00×.

The warning capture uses a separately seeded sample with existing effects. The default three-marker task does not produce that warning. Do not invent a live failure or repeatedly apply batches just to reach a screenshot's count.

Use these short explanations while showing the corresponding state:

  • D2: “This table is our proposed change. We can review the destination and component assignment before creating anything.”
  • D3: “The preview has been used. Repeating the name is blocked, so we need a new name or a fresh practice sample.”
  • D4: “We reuse the same interaction pattern. The rules now describe markers and effect placement instead of textures and material slots.”
  • D5: “Placement checks passed does not mean the effect is cheap. Rendering and optimization work will measure what these count checks cannot.”
  • D6: “The sample lets us study behavior without an editor. The adapter is where we will need to verify real assets, transactions and editor behavior.”

UI/UX progression: the same Material/VFX tools

Use the three assistant stages. Compare Material Setup across stages 1 → 2 → 3, then VFX Placement across 1 → 2 → 3. Keep inputs and window size constant; each stage begins with fresh practice data. Use D2 and D4 as the preview comparison beats, and D3/D5 to compare recovery.

Stage Observe Quality question
1 · Functional Linear text review and explicit actions Can the user inspect and complete the entire task?
2 · Guided Before/after table, scope summary and inline input guidance Can the user find the exact target and compare values without holding them in memory?
3 · Refined Progress cues, counted Apply labels and primary-action emphasis Can the user identify the current step and predict the next action?

Run Scripts/assistants.py --stage N manually, or add --render Docs/UI/captures for offscreen captures. Scripts/ui_quality.py --stage N now gates these assistant stages. The shared session retains all safeguards at every stage. Prop Inspector is retained only as an earlier reference; the UI lesson no longer switches tools. The live Qt host owns one panel. Opening another stage/tool replaces it. Finish the current demo before switching, then reopen and preview again after reload. The native bridge has separate session entry points for props and workflows; close_all() expires both. The original commands and stable IDs are retained.

For future live material rehearsal, restoring component assignments and handling the newly created material asset are separate steps. For VFX, inspect the actual placed Actors and Undo behavior. Neither workflow automatically saves. Follow the live acceptance checklist before presenting these as verified editor operations.

What this cleanup resolved

  • Competing “start here” instructions now converge on Material Setup → VFX Placement. Prop examples remain optional foundations or fallback. The UI progression now uses Material/VFX themselves.
  • The outdated “cleanup or batch import?” decision is resolved to the user's selected tools. Advanced graph editing and scattering remain outside scope.
  • Practice mode now rejects unavailable material slots, parents and presets; previously a changed slot could silently preview the sample's slot 0.
  • Reload, reset and single-window behavior are explicit, rather than implied to apply uniformly to both tool families.
