Tech Art Museum Exhibit Break/Fix Guide

Project: TechArtMuseumIntegration
Audience: Instructor/build team
Updated: 2026-09-09

Sandbox implementation: A separate 12-bay instructor review map now exists at /Game/TechArtMuseum/SandboxGrid/L_ExhibitReviewGrid. See review setup and evidence, exact instructor key, and readiness manifest. The source-map readiness table below is the original integration queue; it does not mean the new pairs have been migrated into the gallery or student maps. Headless configuration, rendering, and gameplay evidence are reported separately.

Answer-key warning: This document names every fault and repair. Do not give the full guide to students before the end-of-Week-2 answer-key review.

Standard for every exhibit

Every station must answer the same five questions:

  1. What is this? The pipeline concept being demonstrated.
  2. What does Correct prove? The intended visual and technical contract.
  3. What was broken in Incorrect? One deliberate fault only.
  4. What is the intended fix? The smallest repair at the authoritative source.
  5. How do we know it is fixed? One visible check and one technical check.

Never edit Correct to make Incorrect. Duplicate it, append _Incorrect, introduce one fault, and keep transform, lighting, camera, animation rate, and unrelated settings matched.

EX24 — Normal Maps Are Direction Data

What it is: Identical meshes and pixels demonstrate that texture metadata and sampler interpretation control the decoded surface directions.

Learning objectives: Recognize normal maps as vector data; connect compression, sRGB, sampler type, tangents, and green-channel convention; diagnose from moving-light evidence.

CORRECT: /Game/TechArtMuseum/PrototypeLab/Materials/M_EX24_NormalMap_Correct. Normal compression, sRGB = false, Normal sampler, project Y convention.

INCORRECT — break: Use /Game/TechArtMuseum/PrototypeLab/Materials/M_EX24_NormalMap_Incorrect. Interpret the normal map as color data. Do not also change UVs, tangents, mesh, or light.

Intended fix: Set Normal Map compression, disable sRGB, use a Normal sampler, and confirm the project green-channel convention.

Verify: Highlights and fine detail match Correct under several light directions; texture metadata matches while mesh/material inputs remain controlled.

Popup: Observe warped highlight → identify direction-data contract → inspect texture/sampler → repair classification → verify under moving light.

Reference: https://dev.epicgames.com/documentation/unreal-engine/texture-compression-settings-in-unreal-engine

EX23 — RGB, sRGB, and Packed Data

What it is: The same pixels are interpreted as display color and numeric mask data, demonstrating where gamma conversion belongs.

Learning objectives: Separate color from data; inspect individual RGB channels; trace import metadata through sampler and shader input.

CORRECT: /Game/TechArtMuseum/PrototypeLab/Materials/M_EX23_ColorVsData_Correct. Base Color remains sRGB; packed masks are linear and use documented channels.

INCORRECT — break: /Game/TechArtMuseum/PrototypeLab/Materials/M_EX23_ColorVsData_Incorrect. Enable sRGB on the packed mask only; do not also swap channels.

Intended fix: Disable sRGB for the numeric mask and confirm each channel feeds the documented scalar input.

Verify: Metallic/roughness response matches Correct under one light; packed texture is linear while Base Color stays sRGB.

Popup: Color or data? → inspect channels → find gamma conversion → repair metadata → verify PBR response.

Reference: https://dev.epicgames.com/documentation/unreal-engine/physically-based-materials-in-unreal-engine

EXALPHA — Alpha Blending (Colleague Addition)

2026-09-09 audit correction: The two colleague master materials also have different default Base Color values; their presence/compilation alone did not prove a single controlled blend-mode fault. The sandbox EXMAT-B pair clones MM_Alpha_01, gives both the same opacity/color graph, and changes only Blend Mode. The original colleague Blueprints and gallery are preserved.

What it is: Two pairs of intersecting torus meshes compare a translucent material contract with an opaque one.

Current assets and placement

  • Map: /Game/TechArtMuseum/Maps/TechArtGallery_Interactive_AuthorMerge
  • CORRECT candidate: /Game/Showcase/Blueprints/BP_Alpha_Example
  • INCORRECT candidate: /Game/Showcase/Blueprints/BP_Alpha_Example1
  • Shared mesh: /Game/Showcase/Meshes/torus
  • Correct family: MM_Alpha_01 / MM_Alpha_01_Inst — Translucent.
  • Incorrect family: MM_Alpha_02 / MM_Alpha_02_Inst — Opaque.

Learning objectives: Distinguish Opaque, Masked, and Translucent; explain visibility, sorting, and overdraw tradeoffs; locate a blend-mode fault in the material rather than the mesh.

CORRECT: Design requirement: both colored interlocking surfaces remain partially visible through one another. BP_Alpha_Example uses Translucent materials on both components.

INCORRECT — what is broken: BP_Alpha_Example1 uses Opaque materials, so the front surface hides the rear. Do not change component transforms.

Intended fix: Duplicate the student material, restore Translucent blend mode and the Correct opacity input/parameter contract. Do not move the torus components to fake visibility.

Verify: Both forms remain readable through overlap from several angles; both Blueprints retain identical mesh/component transforms and differ only in material contract.

Popup: What should remain visible? → compare overlap → inspect Blend Mode/Opacity → repair → discuss sorting and overdraw.

Reference: https://dev.epicgames.com/documentation/unreal-engine/material-blend-modes-in-unreal-engine

EXMAT — Maya → Unreal Material Contract

What it is: Maya shading groups/material IDs become Unreal slots, while Unreal controls runtime blend behavior. Use two small pairs; do not combine faults.

EXMAT-A — Slot order

  • CORRECT: Two distinct surface regions import into named slots in documented order.
  • INCORRECT — break: In a Maya duplicate, swap face-to-material assignments or rebuild shading groups so slot order changes.
  • Intended fix: Restore deterministic shading groups and face assignments in Maya; re-export/reimport.
  • Verify: Each region has the intended material; names/order survive reimport at actor scale (1,1,1).

EXMAT-B — Blend mode

  • CORRECT: Use Opaque for solid surfaces, Masked for hard cutouts, or Translucent for partial coverage according to the stated requirement.
  • INCORRECT — break: Assign the wrong blend mode only. Candidate source: TestOpaque versus TestBlend under /Game/TechArtMuseum/CandidateAssets/AlphaBlendModeTest/.
  • Intended fix: Restore the intended blend mode and connect Opacity/Opacity Mask only where required.
  • Verify: Silhouette/overlap matches Correct and slots remain unchanged.

Reference: https://dev.epicgames.com/documentation/unreal-engine/fbx-material-pipeline-in-unreal-engine

EXLOD — LOD Generation and Distance Switching

2026-09-09 measured implementation: The imported coil has Nanite enabled. Its original 7,106-triangle conventional fallback is not the 150,000-triangle source mesh. Both sandbox copies disable Nanite; Correct contains real 150,000 / 52,500 / 15,000 triangle LODs, and Incorrect contains only 150,000. Saved screen thresholds are 1.00 / 0.50 / 0.30. Reduction slightly expands the derived bounds, so explicit extensions match both final bounds. See the sandbox key for the exact repair and camera evidence; distance alone does not specify LOD without FOV/aspect.

What it is: A dense scan is shown twice so students can see lower-detail meshes replace LOD0 as projected screen size decreases.

Recommended source: /Game/TechArtMuseum/CandidateAssets/PageInductionCoil/page-induction-coil-150k-4096/StaticMeshes/page-induction-coil-150k-4096

Learning objectives: Read LOD index/triangle count/screen size; judge silhouette preservation and popping; relate LODs to production automation such as Simplygon/HLOD.

CORRECT — author first: Duplicate to SM_InductionCoil_LOD_Correct; generate/import LOD0, LOD1, and LOD2 with deliberate screen-size thresholds. Preserve silhouette, materials, bounds, and collision.

INCORRECT — break: Duplicate Correct to SM_InductionCoil_LOD_Incorrect; remove LOD1/LOD2 so only dense LOD0 remains. Do not also change Nanite or scale.

Intended fix: Generate/import a silhouette-preserving chain and tune thresholds. Do not hide or scale the actor.

Verify: No objectionable pop at museum range; forced-LOD/stat view shows decreasing triangles while materials/bounds/collision stay stable.

Popup: Walk backward → watch LOD index/triangles → inspect thresholds → generate/tune → connect to automated pipelines.

Reference: https://dev.epicgames.com/documentation/unreal-engine/static-mesh-automatic-lod-generation-in-unreal-engine

EX20 — Geometry Integrity / Mesh Autopsy

What it is: Small mesh pairs isolate topology and face-orientation failures. The existing wall contains Incorrect examples; selected faults still need matched Correct partners. Use at most three as Lab 2 repair tasks.

Fault CORRECT INCORRECT — break Intended fix Verification
Reversed face Consistent intended winding/outward normals. Reverse one visible face. Existing source: /Game/Showcase/MuseumExhibits/geometry/01_synthetic_flipped_normals. Identify the face; reverse/conform only the faulty region; re-export. One-sided shading matches; UVs/IDs unchanged.
Open boundary Closed solid where required. Delete one face. Bridge/fill intended boundary; repair affected normals/UVs. Border-edge test passes; silhouette matches.
Non-manifold Valid manifold neighborhoods. Create one non-manifold edge via localized extrude/merge. Use Cleanup; separate/delete/rebuild owning faces. Non-manifold test returns zero.
Lamina / Z-fighting One surface occupies the location. Duplicate one coplanar face. Delete duplicate; merge only genuinely shared vertices. Flicker disappears; face count matches.
Degenerate face All faces have meaningful area. Collapse two vertices of one face. Rebuild/delete zero-area face; restore local flow. Degenerate test passes; silhouette unchanged.

Do not use “unlock normals and conform everything” as a universal fix; students must identify the owning topology or winding fault.

Reference: https://help.autodesk.com/view/MAYAUL/2026/ENU/?guid=GUID-22A2B5DD-8720-4CE8-B54D-8FA3A8F8C2E3

EXTEXMIP — Mips and Compression

What it is: A high-frequency texture viewed near/far exposes aliasing, shimmer, and mip behavior.

  • CORRECT: Suitable compression preset with generated mips.
  • INCORRECT — break: Duplicate the texture; set Mip Gen Settings to NoMipmaps. Do not also change compression.
  • Intended fix: Restore mip generation appropriate to source and viewing range.
  • Verify: Far view stops shimmering; near view and channel meaning remain correct.

Reference: https://dev.epicgames.com/documentation/unreal-engine/texture-format-support-and-settings-in-unreal-engine

EXNIAGARA — Bounds and Runtime Cost (Optional)

What it is: A small effect demonstrates that visibility bounds and spawn budget are part of the runtime contract.

  • CORRECT: Bounded effect with a stated spawn/count budget.
  • INCORRECT — break: Undersize fixed bounds so particles disappear at a marked viewpoint. Do not also increase spawn rate.
  • Intended fix: Calculate/set bounds enclosing the intended simulation; verify budget.
  • Verify: Effect remains visible from marked viewpoints and profiler counts stay within budget.

Build acceptance checklist

  • Correct and Incorrect are side-by-side under matched conditions.
  • Incorrect contains exactly one fault.
  • Student assets are duplicates; shared source remains untouched.
  • Both versions use the interaction framework, or are labeled observation-only.
  • Popup names the concept/evidence, not only the asset.
  • Student map omits the fix; instructor key includes it.
  • Each station has a repeatable reset path.
  • Existing First Person interaction path remains unchanged.

Interaction limitation

2026-09-09 validation correction: Earlier READY and Blueprint compile/default checks are asset-configuration evidence, not gameplay or render acceptance. The sandbox independently verifies the saved faults. Its EX23 pair keeps compression identical while isolating sRGB interpretation; EX24 isolates only the green-channel convention (the imported Correct baseline is Flip Green Channel = true). The old prototype EX23 and EX24 materials change several settings and are not the narrower sandbox controls.

The sandbox assessment meshes encode their display materials in default slots, and skeletal stations use dedicated skeletal presentation Blueprints. All assessment pairs are explicitly observation-only. The entry retains a separate working static E-inspection smoke test. Limited Play probes and physical E/R keyboard testing must be distinguished; refer to the current evidence report.

BP_MuseumExhibitItem_Test exposes its inherited Static Mesh through Item.ItemMesh. Material-only variants may need a mesh with encoded default materials or a small payload extension that copies component overrides. Skeletal Meshes, animations, morph targets, and Niagara systems need purpose-built presentation actors; do not force them through a Static Mesh field.

Packaging-space note

No unused assets were deleted. Zero hard references do not prove an asset is unused: soft references, Asset Manager rules, string loads, always-cook directories, and external data can keep it live. Build a dependency-closure report and quarantine/cook test before deletion.
