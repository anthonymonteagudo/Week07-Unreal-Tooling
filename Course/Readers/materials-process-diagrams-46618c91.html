1. Authoring, preparation, and assignment

Vector version

flowchart TB
    Graph["UE Material graph + settings"] -->|compiled with engine code| Compiler["Shader compilation"]
    Compiler -->|produces| Programs["GPU shader programs"]
    Graph -->|exposes named controls| Instance["Optional Material Instance"]
    Texture["Texture Assets + import settings"] -->|referenced by| Graph
    Texture -->|selected by texture parameters| Instance
    Graph -->|can be assigned directly| Assignment["Mesh component material slot"]
    Instance -->|can be assigned| Assignment
    Mesh["Mesh geometry + attributes"] -->|defines sections and defaults| Assignment
    Assignment -->|selects surface setup| Draw["Engine prepares rendering work"]
    Mesh -->|provides positions, normals and UVs| Draw
    Texture -->|built into texture resources| Draw
    Programs -->|executed during| Render["GPU rendering"]
    Draw -->|binds data and state for| Render
    Scene["Camera, lights and environment"] -->|provide scene context| Render
    Render -->|produces through multiple passes| Image["Displayed image"]

Read the shader/program branch first. Then follow the instance and assignment branch. The engine prepares resources for rendering. A texture is referenced and sampled, not transformed into a Material. A Material Instance is optional.

The PNG/SVG use a compact grouped representation of the same relationships. “Engine prepares rendering work” combines resource preparation, selection, and binding for readability. This is not an exact frame scheduling diagram.

2. How one texture value contributes to appearance

Vector version

flowchart LR
    UV["Mesh UVs or generated coordinates"] -->|locate a sample| Read["Texture sample and interpretation"]
    Tex["Texture resource + import settings"] -->|provide data and decoding| Read
    Sampling["Sampler rules and available mips"] -->|control lookup| Read
    Read -->|returns values| Math["Channel selection and graph operations"]
    Param["Constants and instance parameters"] -->|supply other values| Math
    Math -->|calculate| Surface["Surface attributes: Base Color, Roughness, Normal..."]
    Surface -->|contribute to| Rendering["Rendering passes and lighting"]
    Scene["Geometry, camera and scene context"] -->|also contribute to| Rendering
    Rendering -->|scene image through exposure and display processing| Screen["Displayed image"]

This is a dependency diagram for a common surface-texture workflow. Reading, decoding, and filtering are grouped for clarity, not placed in a claimed hardware execution order. A compiler can fuse or reorganize operations. A deferred path can store surface attributes in intermediate buffers before lighting.

Some inputs use constants or procedural calculations without texture sampling. Normal textures involve direction decoding and space conversion. Texture dimensions, mips, and shading values are distinct from mesh topology and LODs.

Technical references: Epic: Essential Material Concepts, Epic: Graphics Programming Overview, LearnOpenGL: Textures.
