Writing Your First Python Test for Unreal — REFINED

Course index · Original notes

The Python Automation Test plugin discovers scripts named test_*.py in discoverable Python locations. A discovered script still needs to execute its checks: merely defining a function does not run it.

Separate project tests from unrelated packages

The Python category may include tests bundled with Python Foundation Packages. Some expect a separate framework or dependencies such as pytest; discovering those files does not automatically adapt them to Unreal's runner.

Why a discovered test file may not execute its checks

The package screenshots contrast framework conventions. For example, pytest can collect a named function, whereas a standalone script that merely defines it does nothing:

def test_upper():
    assert "foo".upper() == "FOO"

A unittest.TestCase uses a runner such as unittest.main(). The course's Unreal script examples explicitly call their check functions and report failures through Unreal logging. Python assert itself is valid; the important distinction is how the file is discovered, how the test is invoked, and how that runner receives failures. Do not interpret an uncalled function as a passed check.

For the course demonstration, exclude the unrelated package tests with a reason, then select the Python Script Plugin examples. Treat this as narrowing the demonstration, rather than resolving the excluded failures.

Read Unreal's examples

Add the engine plugin's Content/Python directory to the IDE's content roots if needed. Inspect examples such as test_type_hints.py, test_wrapper_types.py, and test_source_control.py to see how checks, error logging, and explicit test calls are organized.

Run the selected examples and inspect both errors and warnings.

Write and call a minimal check

Save a project script such as test_string_helpers.py in a discoverable Python folder. The essential pattern is:

import unreal

def test_upper():
    actual = "foo".upper()
    if actual != "FOO":
        unreal.log_error(f"Expected FOO, got {actual!r}")

if __name__ == "__main__":
    test_upper()

The check logs an error when its expectation fails. Unreal's example scripts also explicitly call their test functions.

Prove that failure is detected

Add an intentionally failing check, refresh the Automation test list, and run the script. In the first attempt below, the new function is defined but never called, so the script appears to pass.

Call the failing function and rerun. Its error should now appear in the test result and log. Remove the deliberate failure after verifying the test wiring.

Keep test side effects contained

The source-control example can create or modify files. Inspect its paths and cleanup behavior before running it against working content; keep test assets isolated and restore their state afterward.
