Calling Python Through the Remote Control API — REFINED

Course index · Original notes

Expose an Unreal-recognized Python class, then call its functions from an HTTP client. The course uses Insomnia for exploration and generates Python client code afterward.

Register a callable class

Decorate an unreal.Object subclass with @unreal.uclass() and exposed methods with @unreal.ufunction. Declare the return type and metadata in the decorator.

import unreal

@unreal.uclass()
class RemoteControlDemo(unreal.Object):
    @unreal.ufunction(ret=bool, meta=dict(Category="TechArtCorner"))
    def ping_unreal(self):
        return True

Execute this definition inside Unreal before calling it remotely.

Send the first request

Enable the Remote Control API and check its HTTP Server Port in Project Settings. The demonstrated endpoint is http://localhost:30010/remote/object/call; the web interface uses a different port.

Create a PUT request and choose a JSON body, which supplies Content-Type: application/json. An empty or invalid body can produce a server error response; no connection requires checking the running server, host, and port first.

Use the class default object's path and the exact function name:

{
  "objectPath": "/Engine/PythonTypes.Default__RemoteControlDemo",
  "functionName": "ping_unreal"
}

The response should contain ReturnValue: true.

Pass parameters and return structured data

Declare parameter types in order with params=[int, str]; the method accepts the matching arguments after self. The course's attempted list/tuple return declarations fail. Its workaround is a single string return containing JSON-serialized data:

@unreal.ufunction(ret=str, params=[int, str],
                  meta=dict(Category="TechArtCorner"))
def return_params(self, integer, string):
    return json.dumps({"integer": integer, "string": string})

Place this method inside the class and add import json. Re-execute the updated class in Unreal; the demonstrated editor reinstantiates it.

Change functionName to return_params and add the named parameters:

{
  "objectPath": "/Engine/PythonTypes.Default__RemoteControlDemo",
  "functionName": "return_params",
  "parameters": {"integer": 1234, "string": "It's alive!"}
}

The outer response is JSON; its ReturnValue is another JSON string. Decode that string to recover the dictionary. This pattern suits small serializable results rather than bulk asset data.

Move the request into an external tool

Use Generate Client Code to inspect Python, shell, or other client examples. For the Python requests option, install the package into the external tool's interpreter.

Send the generated request and inspect status, response text, and decoded data. With requests, the final dictionary can be obtained with json.loads(response.json()["ReturnValue"]) after confirming the request succeeded.

External Python request and two levels of JSON

Run this in the external tool after registering the example class inside Unreal and starting the demonstrated server:

import json
import requests
response = requests.put(
    "http://localhost:30010/remote/object/call",
    json={"objectPath": "/Engine/PythonTypes.Default__RemoteControlDemo",
          "functionName": "return_params",
          "parameters": {"integer": 1234, "string": "It's alive!"}},
    timeout=10,
)
response.raise_for_status()
outer = response.json()
payload = json.loads(outer["ReturnValue"])
print(payload)

The timeout and HTTP-status check are audit additions. The inner decode is needed because this particular function returns a JSON string. The earlier Boolean ping_unreal result does not need another json.loads call.
