Remote Control Python Progress Bar — REFINED

Course index · Original notes

An external tool may need to start an Unreal progress dialog, update it across several API calls, and close it afterward. Unlike a single with ScopedSlowTask(...) block, this example keeps the task and its progress state alive between calls.

Keep shared state

Store the active ScopedSlowTask in a module-level variable initialized to None. Store total steps and current step in a small dataclass, both initially zero. Use a unique Unreal class name such as ProgressBarTechArtCorner; ProgressBar conflicts with an existing Unreal type.

Implement all three operations before testing

Start takes steps and label, declares params=[int, str], and returns a Boolean. Reject a second start while a task exists. Create the slow task, set the state's total steps and reset its current step, call __enter__(), and display it with make_dialog().

The later correction below adds the initially omitted total-step assignment.

Increment returns false if there is no active task or no remaining work. Otherwise, increment the counter and call enter_progress_frame(1).

Use current_step < steps before incrementing. The screenshot's <= allows one extra increment and should not be copied unchanged.

Finish exits the scope, clears the active task back to None, and resets the state. Return true after successful cleanup, or false if there was no active task. The demonstrated API's __exit__ parameters are optional.

Corrected boundary and cleanup fragments

Within the increment method, test state.current_step < state.steps before increasing the counter. Reject nonpositive step totals when starting a task. Within the Boolean finish method, successful cleanup must explicitly return True; omitting it returns Python None despite the declared Boolean interface.

The essential cleanup sequence is:

# Method fragment: progress_task and state refer to the retained module state.
progress_task.__exit__(None, None, None)
progress_task = None
state.steps = 0
state.current_step = 0
# The enclosing Boolean finish method then returns True.

Declare the relevant module variable global inside a method that reassigns it. Implement and test finish before exposing start; an external caller should invoke finish from its own finally block. This multi-request lifetime is more fragile than the single-scope progress loop in lesson 33.

Register the complete class before starting a remote task. The early demonstration starts a modal dialog before implementing the finish operation and must restart Unreal to recover.

Exercise the lifecycle remotely

Execute the complete code in Unreal. Send a JSON PUT request to http://localhost:30010/remote/object/call:

{
  "objectPath": "/Engine/PythonTypes.Default__ProgressBarTechArtCorner",
  "functionName": "progress_bar_start",
  "parameters": {"steps": 4, "label": "It's alive!"}
}

Duplicate the request for progress_bar_increment and then progress_bar_finish. Neither requires the parameters object; remove its preceding comma as well so the JSON remains valid. Verify the Boolean response for each operation. The external tool should finish the task even if its own processing fails.

Investigate progress overflow

The lesson shows an overflow warning during manual testing and a later run without it. Keep the total work, increment count, and scope lifetime consistent; a faster run alone does not establish why an earlier overflow occurred. In particular, correct the increment boundary above before reusing the example.
