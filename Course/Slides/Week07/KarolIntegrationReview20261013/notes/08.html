Running Scripts via the Command Line — REFINED

Course index · Original notes

Command-line execution is useful for batch asset processing and build automation. Choose the execution mode according to the editor state your script needs.

Full editor or headless execution

Full editor: loads the project and startup level before running the script. It provides more editor initialization but takes longer to start.

Headless commandlet: runs without the editor interface and skips much of that initialization. Scripts may need to load their required assets or levels explicitly.

The course uses these argument patterns; replace the executable, project, and script paths with your own:

UnrealEditor.exe "C:/Projects/MyProject.uproject" -ExecutePythonScript="C:/Scripts/my_script.py"
UnrealEditor.exe "C:/Projects/MyProject.uproject" -run=pythonscript -script="C:/Scripts/my_script.py"

Check executable and path details

Locate the correct Unreal executable in the engine installation; its name can differ between versions. Quote paths containing spaces, and check slash direction if Unreal cannot find the script. Use the dedicated Python arguments shown above instead of startup ExecCmd plus py.

A discoverable script can be passed by filename, such as hello.py, instead of its absolute path.

Verify execution

The demonstration modifies hello.py to write an empty file with a unique name. That output provides visible evidence that the script ran after the process exits.

Run once with the full editor and once headlessly, then check for the generated files.
