Power of Two Texture Size Validator — REFINED

Course index · Original notes

Keep the allowed-dimensions rule separate from the square-texture rule. Independent validators make each policy easier to change, diagnose, or disable.

Separate dimension limits from power-of-two rules

The size validator is a separate constraint: compare both width and height with the configured limit. Test exactly at the limit, one dimension over it, and both dimensions over it. A texture can satisfy the power-of-two rule from lesson 23 and still exceed the project's size budget. Keep the limit and the reported failing dimension visible in the message.

Define supported sizes

Restrict validation to Texture2D. The course uses an explicit tuple:

valid_sizes = (2, 4, 8, 16, 32, 64, 128, 256, 512, 1024, 2048, 4096, 8192)

This is an allowed-size policy, not a general test for every mathematical power of two: for example, it excludes 1 and values above 8192.

Check both dimensions

Read X and Y using blueprint_get_size_x() and blueprint_get_size_y(). Fail when either dimension is absent from valid_sizes.

Call asset_fails() with a message describing the allowed dimensions and return INVALID; otherwise, return VALID.

Register both validators

Extend the texture-registration function to instantiate and add the new validator alongside the square-texture validator. Remove the temporary standalone registration call when normal startup registration takes over.

Test the rules independently

Validate the mixed texture selection. Some textures should fail only the square rule, some only the allowed-size rule, some both, and some neither. Review the distinct messages in the Message Log.
