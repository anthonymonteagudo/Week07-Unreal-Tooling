Build a batch validator that identifies textures by naming suffix, checks their compression, and optionally fixes mismatches. The suffix-to-compression mapping must reflect the project's naming and shader conventions.

Start with normal maps

The course begins with _N normal maps; the naming reference also lists suffixes for diffuse, emissive, masks, roughness, and other texture roles.

List assets in the target directory, load each one, and skip anything that is not unreal.Texture2D. Then restrict the first version to names ending in _N. list_assets() searches subdirectories unless recursive listing is disabled.

Read and change compression

Find the Texture Editor setting, then confirm its Python property name and type. Here it is compression_settings, with values from unreal.TextureCompressionSettings.

Read the current value with get_editor_property("compression_settings"). Compare it against TC_NORMALMAP; only report or change it when they differ. Apply the change through set_editor_property().

Test a deliberate mismatch

Give a test normal map an incorrect compression setting, save it, and execute the script. The course's first test uses py fix_normalmap_compression.py in Cmd mode.

The example log includes path-format deprecation warnings. Filtering those warnings makes the demonstration's messages easier to see, but does not resolve the underlying warnings. Locate the reported asset and check its compression in the editor.

Separate validation from fixes

Wrap the code in a function accepting a directory and an apply_fix flag. Report mismatches in either mode; modify assets only when the flag is enabled. Use an if __name__ == "__main__": entry point so the script can be run directly or imported by another tool.

Expand the naming rules

Use a dictionary mapping suffixes to compression enum values. Convert get_fname() to a string, find a matching suffix, and skip names with no rule. Use the selected compression value for both the comparison and setter.

Compression rule and validation loop

The final lesson rule uses _N for normal maps, _D and _E for default compression, _R for grayscale, and _M for default compression. _M starts as grayscale in an intermediate screenshot, then changes because the demonstrated mask texture packs multiple channels.

This consolidated version accepts loaded textures and defaults to reporting. It makes the report/apply distinction explicit; supply apply_fix=True only for the intended edit.

import unreal

COMPRESSION_BY_SUFFIX = {
    "_N": unreal.TextureCompressionSettings.TC_NORMALMAP,
    "_D": unreal.TextureCompressionSettings.TC_DEFAULT,
    "_E": unreal.TextureCompressionSettings.TC_DEFAULT,
    "_M": unreal.TextureCompressionSettings.TC_DEFAULT,
    "_R": unreal.TextureCompressionSettings.TC_GRAYSCALE,
}

def check_compression(textures, apply_fix=False):
    for texture in textures:
        if not isinstance(texture, unreal.Texture2D):
            continue
        expected = next((value for suffix, value in COMPRESSION_BY_SUFFIX.items()
                         if texture.get_name().endswith(suffix)), None)
        if expected is None:
            continue
        actual = texture.get_editor_property("compression_settings")
        if actual == expected:
            continue
        unreal.log_warning(f"{texture.get_path_name()}: {actual} -> {expected}")
        if apply_fix:
            texture.set_editor_property("compression_settings", expected)
            if texture.get_editor_property("compression_settings") != expected:
                raise RuntimeError(f"Compression did not update: {texture.get_path_name()}")

The explicit readback above is an audit addition. It verifies the property after the write; it does not save the asset. A folder-based caller must first load each path returned by the asset query. Naming conventions are project rules, not universal texture semantics.

The initial mapping proposes grayscale for some single-channel maps. The final demonstration uses Default for Starter Content's _M textures to preserve that content's conventions. Treat these mappings as project decisions.

Verify the batch result

Introduce several mismatches, run the expanded script, and inspect its messages and changed textures. Save the intended asset changes after review.
