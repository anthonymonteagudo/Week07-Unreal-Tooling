Nested Menus and Menu Entry Initialization — REFINED

Course index · Original notes

Extend the earlier menu example with easier menu discovery, nested submenus, separators, and a comparison of script entries with manually constructed entries.

Reveal menu names directly

In Output Log Cmd mode, run ToolMenus.Edit. Open a menu to see its full name, such as ContentBrowser.AssetContextMenu.StaticMesh. The gear opens a menu editor that also exposes hierarchy information.

Keep the script entry lifecycle

The working sequence remains: get ToolMenus, find the target, instantiate a ToolMenuEntryScript subclass, call init_entry(), register it, assign optional icon data, and refresh widgets.

The expanded example uses two differently named script classes with distinct messages so their execution can be distinguished.

Add a nested submenu

Built-in nested menus illustrate the intended structure. Call add_sub_menu() on the parent and keep the returned menu for later additions.

Its internal path is the parent path plus . plus the new menu's name argument. The visible label is separate; the example's argument values can make those roles easy to confuse.

Add a separator and script action

Create a ToolMenuEntry with MultiBlockType.SEPARATOR, then add it to the submenu with add_menu_entry(). Use meaningful sections to group actions; the demonstration also shows an empty section name.

Initialize and register the script action against the new submenu, then assign its icon as before.

Understand the incomplete manual entry

A manually created ToolMenuEntry can reference a script object through script_object. However, the demonstration supplies an uninitialized script object: it executes but does not display the expected label or tooltip. Setting the outer entry's label alone does not resolve that example.

Initialize the script object's entry data first. For ordinary Python actions, the direct script-entry workflow is simpler than constructing both objects separately.

Match entry types to their containers

MultiBlockType lists menu entries, separators, toolbar controls, and other types. Their presence in the enum does not mean every menu supports them. The course's context-menu experiments produce unsupported-type warnings.

Use the demonstrated menu-entry and separator types for this workflow. More elaborate UI may require APIs or C++ implementation beyond the lesson's Python examples.
