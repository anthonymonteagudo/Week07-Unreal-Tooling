Progress Bars for Slow Tasks — REFINED

Course index · Original notes

Long Python operations can block editor interaction. Use ScopedSlowTask to show progress and provide cancellation between units of work.

Create a scoped task

Pass the total work amount and a dialog message to unreal.ScopedSlowTask. Keep it in a with block so the task is closed when the block exits.

Complete progress-loop pattern

This reproduces the course's 100-step simulation. The sleep only makes the dialog visible; replace it with real work in a tool.

import time
import unreal
with unreal.ScopedSlowTask(100, "Processing examples") as progress:
    progress.make_dialog(True)  # Show a Cancel control.
    for index in range(100):
        if progress.should_cancel():
            break
        time.sleep(0.1)
        progress.enter_progress_frame(1, f"Completed {index + 1} / 100")

Cancellation is cooperative: the loop checks between work units. It stops remaining work and does not undo completed edits. Keep total work and progress increments consistent.

Call make_dialog(can_cancel=True) to display a cancelable dialog. For work that is usually quick, use make_dialog_delayed() so the dialog appears only after the specified delay.

Advance progress and honor cancellation

Before each unit of work, check should_cancel() and break if requested. Advance with enter_progress_frame(1) for one unit. Showing a Cancel button alone does not stop the script; the loop must check it.

Python scripts block unreal interface until they finish.

In case of slow operations, the editor may appear to have frozen.

In such case, we should use a progress bar so the user knows that the editor is still processing and

that he doesn't have to restart the engine.

Let me show you how to implement it.

Slow task code should be wrapped with unreal scoped slow task context manager.

When using the manager it will take two variables.

First is total number of steps and the second one is dialogue name.

In my case there will be 100 steps and dialogue name will be just slow task in progress.

I'm using alias to name that context manager as slow task because we will use it to call methods on

it.

First thing is making sure that the dialogue is visible.

We have to call slow task dot make dialogue and if it was already visible, nothing will happen.

If you want your task to be cancelable, you have to specify can console as true.

Also, you don't have to show make dialogue if your task is not taking a specific amount of time.

In some cases, you will be processing assets and if user selected, only a few of them, effect will

be immediate.

However, if he is processing all assets on the level, it may become a bit slow.

So instead of make dialogue you can use make dialogue delayed.

This time you specify delay as a float value and if that value is exceeded, the progress bar is shown.

Once our dialog is visible, we can run some slow task to simulate it.

I will run a loop that triggers a sleep for a 10th of a second each iteration.

Each iteration should begin with checking if user has clicked cancel button, and if he did, we will

break the loop.

After the iteration, we should advance progress bar by a specific number of frames.

In my case, that will be just a single frame.

Let's call slow task dot, enter progress frame and set it to one.

All that code can now be copied and executed in editor to show how it works.

Paste it.

And let's also check if we can cancel the operation.

We do.

It worked.

knowledge soon at work by.
