Typing in Python — REFINED

Course index · Original notes

Type hints describe the values a variable, parameter, or function result is intended to hold. They improve autocomplete and help an IDE identify mistakes; they do not by themselves enforce types at runtime.

Basic annotations

Use : for parameters and variables, and -> for a function's return type.

def return_string(name: str) -> str:
    return "Here is your string " + name

my_variable: int = 1
another_variable: int
my_list_of_integers: list[int] = [1, 2]
my_dict: dict[str, float] = {"value": 1.5}

An annotation alone does not assign a value. You can also annotate a loop variable before its loop:

i: int
for i in range(10):
    print(i)

Collections and multiple possible types

Built-in collection annotations such as list[int] suit Python 3.9+. For older versions, use types from typing, such as List[int].

from typing import List, Optional, Union

older_style: List[int] = [1, 2]
noneable_var: Optional[str] = None
multiple_types: Union[str, int] = 1
mixed_values: list[Union[str, int]] = ["value", 1]

Optional[str] means str or None. Union[str, int] means either type; str | int is the newer Python 3.10+ notation. A list of mixed values needs one element annotation containing the union. These examples correct the inconsistent union and list syntax in the source notes.

Any permits an unspecified type, while Callable describes a callable such as a function.

Legacy type comments

For older codebases that need comment-based annotations:

def my_function(some_string, value):
    # type: (str, int) -> None
    pass

my_list = []  # type: list

Reference: Python typing documentation and PEP 484.

Typing in Python

This course uses a lot of typed Python code which is still a not popular enough feature but certainly a good one.

Python is a dynamically typed language and most of the Python code you see in web does not use type hints.

No wonder why some of you may be confused when following the course. Everything will clarify soon! This document should enough to get you start using it!

What is Typing in Python

Typing in Python is just a notation used to hint types of variables. It is not only a visual help for developer but also for your IDE.

If your IDE does not detect proper type of the object, you may fix it with type hints.

Thanks to that you will have better auto completion and simple errors will be highlighted.

It does not matter which IDE you use. As long as it supports Python (like VS Code or PyCharm), it will support type hints.

How to use it

Basic typing support was added in Python 2 however it's different in Python 3. We will follow Python 3 notation as that is what Unreal Engine uses however you will find some hints at the bottom of this document if your modules have to be cross compatible.

Let's try adding type hints to a function.

  1. def return_string(name: str) → str:
  2. return "Here is your string " + name

As you can see, we type parameters by adding a colon and type name.

We can do the same for variables. You can but don't have to assign value to variable when writing a type hint.

→ Arrow is only used for specifying return type.

  1. my_variable: int = 1
  2. another_variable: int # this is also correct
  3. my_list_of_integers: list[int] = [1, 2] # typing lists is simple!
  4. my_dict: dict[str, float] = {"value": 1.5} # even dictionaries are simple!

Even loop iterators can be typed!

  1. i: int
  2. for i in range(10):
  3. print(i)

Types from typing module

On Python 3.8 and earlier you may have to make type hints of complex types (List, Set, Dict and Tuple) with types imported from typing module.

  1. from typing import List
  2. my_list_of_integers: List[int] = [1, 2]

But what if my variable can be None or maybe multiple types?

It can be solved with Optional and Union types.

  1. from typing import Union, Optional
  2. noneable_var: Optional[str] # str or None
  3. multiple_types: Union[str | int] # notice | operator!
  4. mutliple_types_arr: list[str, int]

You can also use Any type as a wild card or even Callable type for functions!

Python 2 and 3 compatibility?

You can follow suggested syntax for Python 2.7. It should work fine in IDE's and is based on comments so it is safe to introduce.

Typing functions:

  1. def my_function(some_string, value):

  2. type: (str, int) → None

  3. ^ above you can see parameter and return value types

You can do it also for just specific arguments if you divide function declaration for few lines. It's not the cleanest approach but works.

  1. def three_param_function( param1, param2, # type: int
  2. param3):

The same kind of comment is used for variables in function body.

my_list = [] # type: list
