Removing Unused Assets — REFINED

Course index · Original notes

Build a cleanup tool around the user's selected assets so its scope stays manageable. The lesson identifies candidates through package referencers instead of deleting every apparently unused asset in the project.

Understand references first

Open an asset's Reference Viewer to see which other assets refer to it. The examples contrast a texture used by a material with an unused material that has no incoming references.

Gather selected paths

Get the selection with EditorUtilityLibrary.get_selected_assets(), then convert each loaded object to a path using EditorAssetLibrary.get_path_name_for_loaded_asset(). Keeping the cleanup function path-based also allows reuse with directory queries.

Check referencers before deleting

For each path, call find_package_referencers_for_asset(). The demonstration deletes only when the returned list is empty, using delete_asset(), and logs a warning if its Boolean result indicates failure.

The captured API documentation describes delete_asset() as a force delete that does not perform this reference check for you and may clear undo history. Keep the reference check and limited selection as explicit parts of the tool.

Save before evaluating usage

Save the relevant assets and level first. In the example, an unsaved material uses a texture, but the Reference Viewer initially shows no reference. After saving the material and refreshing, the dependency appears.

Test with both a referenced texture and an unused material. The selected unused asset should be removed while the referenced one remains.

Yield paths one at a time

Refactor the selection helper to yield each path, then call a single-path cleanup function inside the consuming loop. This avoids building a second list of paths, although the selection API still supplies its own collection of loaded assets.

A yielding function should be annotated as an iterator of strings, not simply str; the latter annotation appears in an intermediate screenshot.

Generator and explicit single-asset operation

The final refactor separates selection from the operation. The following mirrors that structure; defining the functions does not execute deletion:

from collections.abc import Iterator
import unreal

def selected_asset_paths() -> Iterator[str]:
    for asset in unreal.EditorUtilityLibrary.get_selected_assets():
        yield unreal.EditorAssetLibrary.get_path_name_for_loaded_asset(asset)

def remove_if_unreferenced(path: str) -> bool:
    if unreal.EditorAssetLibrary.find_package_referencers_for_asset(path):
        return False
    removed = unreal.EditorAssetLibrary.delete_asset(path)
    if not removed:
        unreal.log_warning(f"Could not delete {path}")
    return removed

Save relevant referencing assets/levels before evaluating the result. An empty referencer list is the course's candidate rule, not proof that a dynamically loaded asset is unnecessary. The deletion call is not an Undo demonstration.

For folder-based processing, obtain the Asset Registry through AssetRegistryHelpers.get_asset_registry() and query get_assets_by_path() with the desired recursive setting. A whole-project get_all_assets() query can be expensive on large projects.
