Square Texture Validator — REFINED

Course index · Original notes

Enforce a project's square-texture rule by comparing width and height. This check is separate from power-of-two validation: a 128 × 512 texture passes the latter but is not square.

Prepare contrasting examples

Use square and nonsquare textures. Before the custom validator is registered, the existing validation can report them as valid because it is not checking this rule.

Boundary cases to follow while reading the validator

Check width and height independently: 256 × 512 should pass a power-of-two rule, while 300 × 512 and 256 × 300 should fail. A square-texture rule would be a different requirement. Test an unsupported asset too, which should remain NOT_VALIDATED rather than pass a texture check it never received.

Implement the check

Create an EditorValidatorBase subclass and restrict it to unreal.Texture2D. Compare asset.blueprint_get_size_x() with asset.blueprint_get_size_y().

Register an instance through EditorValidatorSubsystem.add_validator().

Report the failure explicitly

The first implementation returns INVALID without calling the failure-reporting helper. The lesson demonstrates that this does not produce the intended visible failure result.

On a mismatch, call self.asset_fails(asset, unreal.Text("Texture is not square")) and return DataValidationResult.INVALID. Otherwise, return VALID. The message gives the user a concrete reason for the failure.

Verify the Message Log

Run Validate Assets again. Nonsquare examples should now fail with the square-texture validator's message; square examples should pass.

Keep temporary console-test registration separate from normal startup registration so importing the module does not repeatedly add validators.
