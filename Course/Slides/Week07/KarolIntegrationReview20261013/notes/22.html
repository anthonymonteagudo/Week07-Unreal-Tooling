Naming Convention Validator — REFINED

Course index · Original notes

Create an EditorValidatorBase subclass that checks asset prefixes and produces actionable warnings. The course's final example treats a naming mismatch as a warning while leaving the validation result valid.

Define supported assets

Decorate the class with @unreal.uclass() and overridden functions with @unreal.ufunction(override=True). The eligibility method accepts textures, Blueprints, materials, and material instances.

The recording uses can_validate_asset and validate_loaded_asset; its stub already marks older names as deprecated in favor of K2 variants. Match override names and signatures to the engine version being used.

Check the prefix

Convert asset.get_fname() to a string and check the expected prefix:

Asset category Prefix
Texture T_
Blueprint BP_
Material M_
Material instance MI_

The demonstration uses match to organize the cases; older Python versions can use if and elif. Ensure the type dispatch covers the same subclasses accepted by the eligibility check—an exact class comparison is narrower than isinstance().

Return DataValidationResult.VALID for a matching name. For a mismatch, call asset_warning() with a message such as “Name should start with BP_,” then return the result required by the project's policy. Use unreal.Text where the API expects it.

Register and test

Obtain EditorValidatorSubsystem, instantiate the validator, and pass it to add_validator(). Defining the class alone does not register it.

Validator registration and class matching

The screenshots define a decorated EditorValidatorBase subclass, override can_validate_asset(self, asset) and validate_loaded_asset(self, asset), then register an instance:

validator = AssetPrefixValidator()  # Class defined in the preceding screenshots.
subsystem = unreal.get_editor_subsystem(unreal.EditorValidatorSubsystem)
subsystem.add_validator(validator)

Keep the validator instance available for the session. The lesson's class eligibility includes textures, Blueprints, materials, and material instances. Use inheritance-aware checks such as isinstance(asset, unreal.Texture) when a rule should include Texture2D; an exact asset.__class__ == unreal.Texture comparison excludes subclasses. Prefixes are project policy. Return a validation result consistent with the emitted pass/fail messages; use NOT_VALIDATED for assets the rule does not handle. These override signatures are historical course examples—check the installed engine's base class before reusing the whole validator.

Validate selected examples and inspect the warning messages.

Call the registration function from init_unreal.py for future sessions. Keep validator registration organized so the team can find, disable, or adapt rules when moving tools between projects.
