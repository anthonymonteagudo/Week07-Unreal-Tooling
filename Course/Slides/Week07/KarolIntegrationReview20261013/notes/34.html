Wrap supported editor changes in ScopedEditorTransaction so a user can undo a tool's work through the normal editor history.

One transaction for a complete batch

The transaction belongs outside the loop when one Undo should cover the batch:

import unreal
with unreal.ScopedEditorTransaction("Course batch operation"):
    for item in items:
        apply_edit(item)

This is a structural fragment: supply items and the actual apply_edit operation from the lesson. The affected operation/objects must participate in Unreal transactions. A transaction is not a universal rollback for asset creation, imports, file writes, saving, or deletion. Verify what one Undo actually restores instead of inferring it from the scope alone.

Define a meaningful transaction

Use with unreal.ScopedEditorTransaction("Operation name"): around the changes. An as variable is unnecessary unless you need to access the transaction object.

Nested transactions appear under the outer transaction in the demonstrated history. A wrapper does not make inherently non-undoable operations undoable; the lesson uses mesh import as an example of that limit.

Group the compression fix as one action

Wrap the texture-compression tool's batch operation in a transaction named Fix Texture Compression. Grouping the batch lets the user undo one tool invocation instead of stepping backward through hundreds of individual assets.

Test undo and redo

Change several test textures to incorrect compression settings, then run the script and inspect the log.

Choose Edit → Undo Fix Texture Compression, check the values, and redo the operation to confirm they are restored.

Inspect transaction details

Open Edit → Undo History and select the transaction. Enable Show Transaction Details to see affected objects and properties.

The recording includes some textures changed before filming, so its transaction contains more assets than the visible setup edits.

Expand individual objects to inspect modified properties. History consumes memory and older operations can be discarded; it is not a substitute for saving or version control.
