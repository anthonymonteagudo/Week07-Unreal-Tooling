Post Import Actions with ImportRules — REFINED

Course index · Original notes

Post-import rules apply consistent processing as source files become Unreal assets. This lesson uses Ryan Dowling Soka's UnrealImporterRules-Python plugin; lesson 17 builds a callback directly with ImportSubsystem.

Plugin roles and folder rules

This note starts partway through the example. The screenshots belong to the UnrealImporterRules-Python approach credited to Ryan DowlingSoka: a query identifies applicable imports, and an action handles the matched object. Keep that plugin/framework dependency distinct from a standalone Unreal script.

The demonstrated destination mapping is environment → Enviro, weapons → Weapons, and deco → Deco under the chosen content root. Retain the query's filtering and inspect the destination construction before enabling an action that moves an asset. Lesson 17 rebuilds the idea with Unreal's import callback directly.

Install and inspect the plugin

The course downloads the repository archive, extracts the plugin into the project's Plugins directory, restarts Unreal, and checks that ImporterRules (Python) is enabled.

Rules combine queries, which decide whether an asset qualifies, with actions, which perform the change. Review the query and action base classes, source-path query, and supplied texture examples before adding a custom rule.

Inspect imported metadata

Import the example FBX and open Asset Actions → Show Metadata. Its FBX.mesh_type tag contains a value such as environment; the rule will use this to choose a destination folder.

Create the query and move action

The custom query reads FBX.mesh_type through EditorAssetSubsystem and accepts recognized values. The action maps that value to a folder, builds a destination under /Game, and appends the existing asset name.

Use EditorAssetLibrary.rename_asset(source_path, destination_path) to move the asset. Keeping the final asset name unchanged makes this a folder move rather than a rename.

Register and initialize the rule

Following the supplied registration example, register a rule for unreal.StaticMesh with lists containing the custom query and action instances. Import the module from init_unreal.py so registration happens at startup.

Verify a fresh import

Restart and import the FBX. The demonstration creates the destination folder and moves the mesh into it. Its metadata then includes importer_rules_applied with the string value True, recording that the rules have run.
