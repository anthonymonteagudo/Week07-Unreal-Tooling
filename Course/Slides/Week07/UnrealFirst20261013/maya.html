A dedicated Maya route

Use this alongside the Blender demonstration. Both use the same Publisher, manifest and Unreal receiver. Maya’s differences are transform/shape selection, centimeters, Y-up coordinates, a temporary export copy and the FBX plug-in.

Written walkthrough, not a newly recorded rehearsal. Existing Maya host/API tests verified import/reimport and source preservation. The image below is an offscreen render of the real publisher. Complete its live button sequence before class.

1. Stage the receiving project

Open the Week07UnrealPython project in Unreal 5.7.4 and the map /Game/Week07/Bridge/W07_BridgeComparison. Identify the two orange Maya instances. In Output Log → Python, run:

from week07_bridge import unreal_receiver
unreal_receiver.install_menu()
unreal_receiver.start()

Read the printed exchange path. Start is explicit each editor session. The publishers and receiver must use the same absolute exchange folder. Default: Saved/BridgeExchange in this project. Take note of each Maya Actor’s transform and material override before sending.

2. Open the baseline and inspect selection

Open BridgeCompare.ma in Maya 2027. Use Select → Object Mode and select the wedge transform in the Outliner. In Windows → Settings/Preferences → Preferences → Settings, verify centimeters. The prepared scene is Y-up.

In the Script Editor’s Python tab, run this read-only segment:

import maya.cmds as cmds

selection = cmds.ls(selection=True, long=True) or []
print("Selected:", selection)
for node in selection:
    print(node, cmds.nodeType(node))
    print(cmds.listRelatives(node, shapes=True,
                             noIntermediate=True, fullPath=True))

Expected: one transform with one non-intermediate polygon mesh shape. Empty selection, a vertex selection, multiple meshes, child transforms, skin/blend shapes, mirrored or zero scale are rejected by this teaching publisher.

Predict: “Will selecting roof vertices provide the transform the exporter expects?” After any vertex edit, return to Object Mode and select the transform.

3. Open the publisher

Run the launcher in Maya’s Python Script Editor. This path is the instructor’s current checkout; students replace it with their extracted project root.

import runpy
runpy.run_path(

Confirm the exchange folder matches Unreal. Keep SM_Compare_Maya. The destination is /Game/Week07/Bridge. Inspect connected status before sending.

4. Publish the baseline and verify

  1. Choose Publish & Send to Unreal. Wait for Imported: and the actual asset path.
  2. In Unreal inspect /Game/Week07/Bridge/SM_Compare_Maya.SM_Compare_Maya. Both Maya-row Actors should still refer to it.
  3. Verify 120 × 60 × 180 cm, floor-level pivot, expected roof direction and both unchanged placement transforms.
  4. Inspect Static Mesh material slots and each Actor’s component override. The orange Unreal material should remain.

Say: “The reply identifies what Unreal actually imported. A file on disk or a Sent message is only an earlier stage.”

5. Raise the roof and publish a revision

  1. In Maya switch to vertex mode. Select the four roof vertices, keeping all floor vertices unselected.
  2. Move those vertices +40 cm in world Y in this Y-up scene. Do not move the whole transform. The maximum height changes from 180 to 220 cm while the floor and pivot remain at zero.
  3. Return to Object Mode and select the wedge transform.
  4. Keep SM_Compare_Maya, then Publish & Send. Wait for a new Imported acknowledgement.
  5. Verify the same Unreal asset path, both instances updated, height 220 cm, original placements and materials intact.

Fallback: open BridgeCompare_Revised.ma and send it under the same asset name. Re-publish the baseline scene under that name to reset. Opening another scene requires the usual review of unsaved changes.

6. What the adapter automates

ExportFBXPushSettings, FBXExport, FBXPopSettingsFile → Export Selection → FBX, static mesh, Z-up export, smoothing and triangulation enabled
Restorefinally removes the copy and restores selection, Undo and modified stateDelete only the temporary export copy; keep the source scene intact

The manual export steps explain the API behavior; for this classroom run use the bridge’s tested export policy. It does not freeze or delete history on the source. FBX export alone does not create the manifest, queue a request or receive acknowledgement. Actual Maya adapter · Shared Publisher.

7. Materials and failure recovery

Source material assignment lives in Hypershade. The bridge imports geometry with material/texture import disabled, retains the existing Unreal mesh slots and leaves placement overrides attached to their Actors. It does not translate Maya shading networks. See the material walkthrough for property-level manual steps.

Observed stateNext action
DisconnectedStart the receiver and compare the absolute exchange paths.
Selection rejectedReturn to Object Mode; select only the mesh transform and inspect its shape, units and scale.
Sent, awaiting acknowledgementInspect Unreal’s Output Log and receiver status before resending. The publisher blocks another pending request.
Unowned destination refusedUse the prepared bridge-owned asset or a fresh asset name. Do not replace unrelated project assets.
Geometry imported but dimensions failedInspect source units, axes and export policy. The receiver reports the unsaved failure; do not present it as a successful revision.

Rehearsal record to capture: baseline and revised acknowledgements; both Unreal instances; dimensions; pivot and axes; material slots and overrides; unchanged Maya transform, selection, source history and scene-modified state. Record failures as failures. Do not substitute the existing Blender click-through for Maya UI evidence.
