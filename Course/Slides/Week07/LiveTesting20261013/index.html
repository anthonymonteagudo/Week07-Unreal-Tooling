1. Prepare Unreal

  1. Open Week07UnrealPython.uproject in UE 5.7.4. Its configured association is 5.7. Use this prepared project for the tests.
  2. Open /Game/Week07/Maps/W07_MaterialVFXLab from the Content Browser. Stop Play in Editor.
  3. Open Window → Developer Tools → Output Log. Set the input selector to Python. All commands labeled Unreal below run there, not in PowerShell or the ordinary console-command mode.

import unreal

Expected: the prepared Unreal version and the Week07UnrealPython folder. If another project appears, switch projects before proceeding.

Unreal: check and stage the classroom scene

from week07_tooling.editor import live_demo
print(live_demo.preflight())

Expected: a message starting Baseline ready. The helper checks the target/protected cubes, baseline materials, textures, effect preset and absence of earlier placed effects. It also moves the viewport to the teaching camera and selects the material target and three textures. It does not reset or rebuild the map.

If the check fails, follow the specific message. Use the reset reference for previous rehearsal changes. Do not run the one-time fixture-construction script on an existing map.

The project enables Python Script Plugin, Editor Scripting Utilities and Week07Tools. The native panel is the compiled Week07Tools Slate plugin. Older documents mentioning a future Editor Utility Widget or starting with PRACTICE MODE describe earlier work.

2. Test the native Unreal UI

Open Tools → Material & VFX Tools. Expect a dockable tab labeled UNREAL EDITOR, with Material Setup, VFX Placement and Reconnect controls.

The native panel uses the prepared classroom surface and fountain automatically. It does not have the same parent/preset dropdowns as PySide. Its editable material inputs are the new instance name and slot; VFX uses effect scale.

2A. Material Setup

  1. After preflight, wait for the Content Browser selection to finish updating. Confirm only W07_Crate_Target is selected in the Outliner and the three T_Crate_BaseColor, T_Crate_Normal, T_Crate_ORM textures are selected in the Content Browser.
  2. Choose Material Setup. Enter a fresh name such as MI_Native_Test_01 and material slot 0. If that name exists, increment it.
  3. Choose Preview changes. Inspect the three texture mappings, the prepared parent and the target's before/after assignment.
  4. Only after the preview matches your intent, choose Apply.

Expected: one new material instance under /Game/Week07/Generated/Materials and one component assignment. The target cube changes; W07_Crate_Protected does not. Apply is consumed and a new preview is required for another operation.

Open the new instance. Parent should be /Game/Week07/LiveDemo/Materials/M_PreparedSurface. Its BaseColorTexture, NormalTexture and ORMTexture parameters should point to the three selected textures. Inspect the target component's Details → Materials → Element 0 assignment.

2B. Verify blocking and material reset

  1. Preview again with the same instance name. Expected: an existing-destination rejection, with no overwrite.
  2. Put focus over the level viewport and Undo the material assignment once. Expected: the target returns to its original material, the protected cube stays unchanged, and the new instance remains in the Content Browser.
  3. Choose a new name for the next test. Use Reconnect if the panel has an expired session, then preview again.

Assignment Undo does not delete the new material asset. The tool does not automatically save either the asset or map. Retain the test instance for inspection or remove only that individual instance after checking that nothing uses it.

2C. VFX Placement

Unreal:

from week07_tooling.editor import live_demo
print(live_demo.select_vfx())

Expected: Three anchors selected. Preview before Apply.

  1. Choose VFX Placement. Set Effect scale to 1.0.
  2. Preview. Expect the three tagged anchors and three proposed effects. With a clean baseline, the effect count should change from zero to three.
  3. Apply. Inspect one fountain at each anchor, with matching position and rotation.
  4. Preview again using those anchors. Expect duplicate-placement rejection.
  5. Focus the level viewport and Undo the placement once. Expect all three effects in that batch to disappear while the anchors remain.

These checks establish placement behavior, not frame cost. The effect graph and simulation settings are not edited by this workflow.

2D. Optional stale-input test

Prepare a material preview using a fresh name. Before Apply, change the Outliner selection to include the protected cube. Apply should refuse the changed inputs rather than execute the old plan. Restore selection with the command below, then make a fresh preview:

from week07_tooling.editor import live_demo
print(live_demo.select_material())

Before switching interfaces: Undo known test changes, close the native tab, and run preflight again. Proceed when it reports Baseline ready.

3. Test the live PySide version

Use the same Unreal project and MaterialVFXLab map. Keep the native tab closed while comparing workflows.

Unreal: open PySide against the real editor

from week07_tooling.editor import live_demo
print(live_demo.preflight())
import week07_tools as w7
w7.show_assistants()

Expected: a PySide Material/VFX window using real Unreal assets and Actor selection. It is an external Qt window parented to Unreal, not the native dockable tab. It must not say PRACTICE MODE.

  1. In Material Setup, choose Classroom blue surface, a new name such as MI_PySide_Test_01, and slot 0.
  2. Repeat the native material sequence: Preview, verify mapping, Apply, inspect both cubes and parameter values, test duplicate-name rejection, then Undo the assignment.
  3. Run live_demo.select_vfx(). In VFX Placement, choose Classroom fountain and scale 1.0.
  4. Repeat the native VFX sequence: Preview, Apply, inspect three placements, confirm duplicate blocking, then Undo the batch.

Pass condition: the results and protections match the native UI. Test with fresh names; an asset created during the native test remains an existing asset during the PySide test.

Unreal: close PySide cleanly

import week07_tools as w7
w7.close_ui()

Expected: the window closes and its UI update callback is removed. This does not undo scene edits, delete assets or reset selections. Use the same material/VFX reset steps, then run preflight again.

Only when Python source has changed during testing

After reviewing any scene edits, close the active tool and use:

import week07_tools as w7
w7.reload_tools()
w7.show_assistants()

Reload closes the shared Qt panel and expires native plans. Reopen the native tab or Reconnect if needed. Always create a fresh preview. Reload is not a scene reset and does not rebuild the C++ plugin.

Running Scripts/assistants.py from a terminal opens the separate sample-data practice interface. It does not test the live Unreal backend.

4. Test the Maya/Blender bridge

Finish and reset the Material/VFX tests first. Review unsaved changes before changing maps. Open /Game/Week07/Bridge/W07_BridgeComparison in Unreal and remain out of Play mode.

The map has two Maya instances (orange) and two Blender instances (blue). Each pair shares one mesh asset. Testing a revision in one source host should update that host's pair.

4A. Unreal: start the receiver

from week07_bridge import unreal_receiver
unreal_receiver.install_menu()
print(unreal_receiver.start())

Expected: a listening message and the absolute exchange folder, normally Week07UnrealPython/Saved/BridgeExchange. Tools gains Start FBX Bridge Receiver and Stop FBX Bridge Receiver. Importing the module by itself does not start the receiver.

Match this exact folder in the Maya and Blender publishers. If a receiver is already running, start returns its current folder. To deliberately change folders, first resolve pending work, then stop and restart with the chosen absolute path.

4B. Maya: baseline, revision, reset

  1. Open BridgeCompare.ma in Maya. Use centimeters and Object Mode. Select the one mesh transform, not its vertices. The supplied scene is Y-up.
  2. In the Script Editor's Python tab, run the launcher below.
import runpy
runpy.run_path(
    r"C:/Users/antho/Perforce/anthony.monteagudo_TechArt/"
    r"anthony.monteagudo/Week07UnrealPython/Scripts/bridge/open_maya.py"
)
  1. Confirm the exchange folder and keep the asset name SM_Compare_Maya. Choose Publish & Send to Unreal. Wait for Imported:, not merely Sent.
  2. In Unreal verify the same asset path, both orange instances, baseline size 120 × 60 × 180 cm, floor-level pivot, expected roof direction and retained materials.
  3. For a reproducible revision, open BridgeCompare_Revised.ma. Review unsaved changes at the scene switch, select its mesh transform and run the launcher again if needed. Keep SM_Compare_Maya and Publish & Send.
  4. Wait for Imported. Verify both orange instances are now 220 cm high, with the same asset path, placement transforms and material assignments.
  5. Reset: reopen the baseline BridgeCompare.ma, select its mesh transform, and Publish & Send using the same name. Verify the height returns to 180 cm in both instances.

For the manual-edit version, raise only the four roof vertices 40 cm in world Y. Return to Object Mode and select the transform before publishing. Keep the floor and source pivot unchanged.

4E. Understand the three publisher actions

ButtonWhat happened
Publish FBX + JSONExports a new revision to disk. Does not request an Unreal import.
Publish & Send to UnrealExports and queues the revision, then waits for acknowledgement.
Send Published RevisionSends the existing exported revision. Does not include later scene edits.

4F. Unreal: stop the receiver after testing

First wait for acknowledgement and inspect the final state. Then run:

from week07_bridge import unreal_receiver
unreal_receiver.stop()

Expected: polling stops and the publisher eventually shows disconnected. Stopping does not undo an import or cancel queued work. Changing the exchange path also does not cancel work in the old folder.
