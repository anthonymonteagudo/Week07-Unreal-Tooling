Direct FBX Export from Blender to Unreal — REFINED

Course index · Original notes

Combine the FBX importer from lesson 19 with the Remote Control functions from lesson 44. Blender exports a file, then asks the running Unreal editor to import that exact file. The button hides repeated steps; it does not eliminate the file handoff.

Follow the complete operation

  1. Export the intended Blender mesh to an FBX file.
  2. Send its disk path and the Unreal destination folder to an exposed Python function.
  3. Create one AssetImportTask, apply the import settings, and import it.
  4. Inspect the returned result and the asset in Unreal.

The opening screenshots show the Example Export button and the resulting imported mesh/material. This is the course demonstration, not a complete production publisher.

Reuse the importer and remote-call interface

The batch importer searched a directory and built tasks in a loop. The exporter already knows its output path, so this version needs neither directory discovery nor a loop. It accepts two strings: source_path and destination.

This consolidated receiver follows the screenshot's settings. Execute its definition inside Unreal, with the Python and Remote Control plugins enabled:

from pathlib import Path
import unreal

@unreal.uclass()
class RemoteImporter(unreal.Object):
    @unreal.ufunction(ret=bool, params=[str, str],
                      meta=dict(Category="TechArtCorner"))
    def import_fbx(self, source_path, destination):
        mesh_data = unreal.FbxStaticMeshImportData()
        mesh_data.set_editor_property("combine_meshes", True)
        mesh_data.set_editor_property("remove_degenerates", True)

        options = unreal.FbxImportUI()
        options.set_editor_property("import_mesh", True)
        options.set_editor_property("import_textures", False)
        options.set_editor_property("import_materials", True)
        options.set_editor_property("automated_import_should_detect_type", True)
        options.set_editor_property("static_mesh_import_data", mesh_data)

        task = unreal.AssetImportTask()
        task.set_editor_property("filename", source_path)
        task.set_editor_property("destination_path", destination)
        task.set_editor_property("destination_name", Path(source_path).stem)
        task.set_editor_property("automated", True)
        task.set_editor_property("replace_existing", True)
        task.set_editor_property("save", False)  # Course testing choice.
        task.set_editor_property("options", options)
        unreal.AssetToolsHelpers.get_asset_tools().import_asset_tasks([task])
        return True

The course returns True after the import call. That means execution reached the return statement; it is not a check of mesh contents, scale, destination, or reimport identity. A stronger tool also inspects task.imported_object_paths and the resulting asset. Replacement is enabled and saving is disabled here; choose those policies deliberately.

Test the endpoint before adding Blender UI

Use Insomnia or Postman to call import_fbx with a known FBX and destination such as /Game/Enviro. Determine the class default object's actual path using lesson 47; the older /Engine/PythonTypes.Default__RemoteImporter path is not reliable for every registration mode/version.

The external client below is a cleaned-up equivalent of the screenshot, with an explicit timeout and response check added. object_path must be the path printed by the receiver in Unreal:

import requests

def send_to_unreal(filepath, object_path, destination="/Game/Enviro"):
    response = requests.put(
        "http://localhost:30010/remote/object/call",
        json={"objectPath": object_path, "functionName": "import_fbx",
              "parameters": {"source_path": filepath,
                             "destination": destination}},
        timeout=30,
    )
    response.raise_for_status()
    if response.json().get("ReturnValue") is not True:
        raise RuntimeError("Unreal did not report a successful call")

Use the configured server port. Install requests in the calling application's Python environment if needed; installing it in Unreal does not install it in Blender. A local path works only if the Unreal process can access the exported file.

Connect Blender export to the request

The screenshot's operator subclasses bpy.types.Operator; its execute(self, context) exports the FBX, then calls send_to_unreal. Its export call uses mesh_smooth_type='FACE', object_types={'MESH'}, and use_custom_props=True.

# Fragment inside the Blender operator; filepath and object_path are configured.
result = bpy.ops.export_scene.fbx(
    filepath=filepath,
    mesh_smooth_type="FACE",
    object_types={"MESH"},
    use_custom_props=True,
)
if "FINISHED" not in result:
    raise RuntimeError("FBX export did not finish")
send_to_unreal(filepath, object_path)

The export-result check is an added safeguard. The captured example does not specify use_selection=True; filtering by object type is not the same as exporting only selected meshes. Decide and display the intended scope before adopting this code.

A bpy.types.Panel adds the operator through layout.operator(...). The course panel lives in the 3D View's sidebar (bl_space_type='VIEW_3D', bl_region_type='UI') under Tech Art Corner. Press N to reveal that sidebar. Register both classes with bpy.utils.register_class; provide matching unregister calls when replacing the tool.

The example catches request exceptions but only prints a reminder to handle them. In a usable tool, report whether export succeeded, whether Unreal received the request, and whether import succeeded. Do not return an apparently successful operator result after swallowing an error. Check failures such as Unreal being closed, Remote Control being unavailable, or an incorrect object path.

Choose destination rules with artists: fixed folder, user selection, source-path convention, or metadata. Keep settings and recovery visible enough that the single button remains understandable. See lesson 47 for the path correction and lesson 48 for dependencies.
