Remote Control Object Paths in Unreal 5.5 and Later — REFINED

Course index · Original notes

These screenshot-only notes document a failure caused by assuming the exposed Python class has the same object path in every execution context. The practical fix is to ask the registered class for its default object's path and use that exact value in the request.

Confirm the class was registered

The example defines RemoteControlDemo with @unreal.uclass() and exposes ping_unreal and return_params with @unreal.ufunction(...). A startup file imports the module containing that class.

The HTTP request returns 400 Bad Request with an object-not-found message even though Output Log confirms that the startup file ran. Successful startup alone does not prove the hard-coded request path is correct.

The Blueprint experiment uses an Editor Function Library and finds Cast To RemoteControlDemo, helping establish that the type is registered. It does not discover the class default object's complete path.

Pasting/executing the class definition directly in the console makes the older request succeed in the demonstrated experiment. This changes the registration context; it is a diagnostic comparison, not the preferred permanent fix.

Replace the assumed path with the discovered path

The earlier request and reference excerpt use /Engine/PythonTypes.Default__RemoteControlDemo.

After importing the actual module inside Unreal, print the class default object's identity:

from remote_control_demo_functions import RemoteControlDemo

object_path = RemoteControlDemo.get_default_object().get_path_name()
print(f"DEBUG PATH: {object_path}")

In this startup-import example, the logged path is:

/Game/Python/remote_control_demo_functions_PY.Default__RemoteControlDemo

This is an observed path for the demonstrated module, not a universal replacement string. Module/package names and registration context matter. Repeat discovery when those inputs or the engine version change.

Copy the logged value into objectPath, keep functionName as ping_unreal, and send the PUT request again. The screenshot shows 200 OK and ReturnValue: true.

Add a path regression check

The final screenshots turn the discovered path into a small automation check. This version makes the explicit test invocation clear:

import unreal
from remote_control_demo_functions import RemoteControlDemo

def test_api_object_path():
    expected = (
        "/Game/Python/remote_control_demo_functions_PY."
        "Default__RemoteControlDemo"
    )
    actual = RemoteControlDemo.get_default_object().get_path_name()
    if actual != expected:
        unreal.log_error(f"Remote Control path changed: {expected!r} -> {actual!r}")

if __name__ == "__main__":
    test_api_object_path()

Save as a discoverable test_*.py file and run it with the course's Python Automation Test setup. Adjust expected to the deliberately supported module path. Defining a function without calling it does not run the check.

This test detects a path change; it does not prove the HTTP server is reachable or the remote operation works. Keep the successful ping and operation-result inspection as separate checks. Apply this correction to the remote examples in lessons 44–46 whenever their historical object paths fail.
