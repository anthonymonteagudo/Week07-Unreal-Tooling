Fixing Import Errors and Packaging Python Dependencies — REFINED

Course index · Original notes

An import failure can mean a missing dependency, a different interpreter/search path, an error inside the imported module, or a circular import. Identify which case applies before installing more packages.

Install into the interpreter that runs the code

The example imports colorama. It fails in a terminal or IDE when that environment cannot find the package. A successful installation in one Python environment does not fix every other environment.

Run pip in a terminal, not at a Python >>> prompt. In PowerShell, a quoted executable path needs the call operator &:

& 'C:/Path/To/python.exe' -m pip install colorama

An explicit interpreter path avoids relying on whichever pip happens to be on PATH. In VS Code, check the selected interpreter as well as the terminal environment.

In PyCharm, the demonstrated route is Settings → Project → Python Interpreter → +, then find/install the package. Verify it by rerunning the import in that interpreter.

Install the project's requirements together

A repository's requirements.txt lists dependencies and may constrain their versions. Install that file into the intended environment:

& 'C:/Path/To/python.exe' -m pip install -r 'C:/MyTool/requirements.txt'

PyCharm can offer to install missing requirements when the file is opened. The course also demonstrates Tools → Sync Python Requirements to generate/update the list, including version-specifier options. Review that list before treating it as the tool's supported dependency set.

Keep Unreal dependencies outside the engine installation

Use Unreal's bundled Python to install compatible packages into a project/plugin Python directory. The historical Windows location shown is Engine/Binaries/ThirdParty/Python3/Win64/python.exe; obtain the actual path from the installed engine rather than copying another machine's versioned path.

Inside Unreal:

import unreal
print(unreal.get_interpreter_executable_path())

For the first demonstration, install into the project's Content/Python folder:

& 'C:/Path/To/Unreal/Python/python.exe' -m pip install --target 'C:/MyProject/Content/Python' colorama

Restart Unreal and try import colorama in the Output Log's Python mode. This changes the target project folder, not the bundled interpreter's site-packages. Packages with native extensions must also match the host's Python/platform requirements.

Package dependencies as a content plugin

The course uses Python Foundation Packages as an example of an engine plugin supplying Python dependencies. Inspect the plugin available in your engine version rather than assuming its package inventory matches the recording.

Create a Content Only plugin through Edit → Plugins → Add. Enable Show Plugin Content if needed, then create Content/Python inside the plugin.

MyProject/Plugins/TechArtCornerPlugin/
  TechArtCornerPlugin.uplugin
  Content/Python/
    colorama/
    colorama-<version>.dist-info/

Install to that folder:

& 'C:/Path/To/Unreal/Python/python.exe' -m pip install --target 'C:/MyProject/Plugins/TechArtCornerPlugin/Content/Python' colorama

The course removes the earlier project-local test copy before testing the plugin copy. Avoid leaving duplicate installations that obscure which one is imported. Its manual removal of two known colorama folders is specific to that test, not a general uninstall recipe for every dependency tree.

After enabling the plugin and restarting, inspect the loaded module:

import colorama
print(colorama.__file__)

The result should point to the plugin's Python folder. This is stronger evidence than an IDE autocomplete result.

Use the plugin's category, version, description and icon to make it recognizable. Plugin dependencies can express required plugins. Sharing the plugin shares its packaged files; disabling it and restarting removes that plugin's normal startup availability.

Use package-qualified imports

The IDE may add a script's own directory to its search path, masking an import that fails inside Unreal. The example has:

Content/Python/example_folder/
  __init__.py
  hello_import.py
  main.py

Keep __init__.py for an ordinary package; it may be empty. Python also supports namespace packages, so the file is not a universal requirement for every importable directory. It is the explicit package structure used here.

from hello_import import hello works in the demonstrated IDE configuration but fails in Unreal. Likewise, import main does not locate example_folder/main.py from the parent search root.

Inside main.py, use:

from example_folder.hello_import import hello
hello()

Then invoke it in Unreal with import example_folder.main. A package-relative from .hello_import import hello is another option when the module is imported as part of the package. Repeated imports are cached; restart or deliberately manage development reloads before testing changed code.

Trace nested failures and circular imports

If importing a tool fails, read the traceback to find the innermost failing import. The outer module can exist while one of its dependencies is missing or broken. The course suggests stepping through imports with a debugger, or isolating imports one at a time when necessary; remember that imports can execute top-level code.

The circular example is main → hello_import → bug → main. It reaches a partially initialized module before the needed name is defined.

Break the cycle by giving modules clear responsibilities and moving shared definitions into a lower-level module. Keep dependency direction clear: UI calls reusable operations; host adapters supply Unreal/Blender/Maya specifics. Code without host dependencies can be reused by multiple interfaces or a command-line tool.

Prefer project/plugin Content/Python for discoverability. Additional search paths can work, but they are another setting to distribute and maintain. See lessons 06 and 27 for discovery and debugger-package setup.
